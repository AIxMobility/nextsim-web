NextSIM Editor 사용자 가이드NextSIM Editor User Guide

NextSIM 하이브리드 교통 시뮬레이터의 입력 데이터를 브라우저에서 시각적으로 만들고 편집하는 도구입니다. 도로 네트워크부터 수요(OD), 신호, 대중교통, 이벤트, 시나리오까지 — 시뮬레이션에 필요한 모든 입력 파일을 하나의 지도 위에서 다룹니다.

A browser tool for building and editing the input data of the NextSIM hybrid traffic simulator. Road network, demand (OD), signals, transit, events, scenarios — every input file a simulation needs, all on one map.

에디터 소개What the Editor is

NextSIM Editor는 네트워크 폴더 단위로 동작합니다. 하나의 네트워크 폴더는 시뮬레이션 한 세트에 필요한 입력 파일 묶음이고, 에디터의 각 워크스페이스가 그중 한 파일을 담당합니다. 모든 워크스페이스는 같은 지도(네트워크 캔버스)를 공유합니다.

The Editor works one network folder at a time. A network folder is the bundle of input files one simulation needs, and each workspace in the editor owns one of those files. Every workspace shares the same map canvas.

화면 구성Layout

  • 상단바 — 좌측에 Inputs(폴더 선택·새 폴더·가져오기·백업)와 워크스페이스 선택 스트립(Scenario ~ Events)이, 우측 끝에 Save XML(현재 워크스페이스용) · Display(표시 옵션) · Help 가 모여 있습니다.
  • 도구 패널 — 상단바 바로 아래 중앙에 뜨는 플로팅 패널로, 현재 워크스페이스의 편집 버튼(Add/Reload 등)이 여기에 모여 있습니다. 워크스페이스를 바꾸면 패널 내용도 함께 바뀝니다.
  • 지도(캔버스) — 편집 대상 네트워크가 그려지는 중앙 영역. Network 워크스페이스에서는 좌측에 세로 도구 레일이 추가로 나타납니다.
  • 에디터 패널 — 속성 표·인스펙터가 담긴 패널. 워크스페이스에 따라 우측 도킹(Network·Signal·Station 등) 또는 지도를 덮는 반투명 오버레이(OD·Scenario)로 열립니다.
  • Top bar — on the left, Inputs (folder selection, new folder, import, backups) and the workspace strip (Scenario … Events). Right-aligned at the far end: Save XML (for the current workspace), Display, and Help.
  • Tools panel — a floating panel centred just under the top bar holding the current workspace's edit buttons (Add, Reload, and so on). Its contents change with the workspace.
  • Map (canvas) — the central area where the network is drawn. The Network workspace adds a vertical tool rail on the left.
  • Editor panel — the attribute tables and inspector. Depending on the workspace it docks on the right (Network, Signal, Station …) or opens as a translucent overlay across the map (OD, Scenario).
상태 메시지는 팝업으로. 저장 완료·검증 경고·오류 같은 실시간 피드백은 패널 안이 아니라 화면 우측 상단 토스트로 뜹니다. 같은 메시지가 연달아 발생하면 한 번만 표시됩니다.
Status shows as a toast. Live feedback — save confirmations, validation warnings, errors — appears as a toast in the top-right corner, not inside the panels. Repeats of the same message are collapsed to one.

저장 모델How saving works

편집 내용은 워크스페이스별로 우측 상단의 Save XML 버튼을 눌러야 파일에 기록됩니다. 저장 전의 변경은 브라우저 안에만 있으며, 다른 워크스페이스로 이동하려고 하면 저장 / 저장 안 함 / 취소를 묻는 창이 뜹니다. "저장 안 함"을 고르면 서버에 저장된 파일을 다시 불러와 편집 전 상태로 되돌립니다. 폴더를 바꾸거나 페이지를 닫을 때도 같은 보호가 걸리며, Events 워크스페이스도 여기에 포함됩니다. 저장할 때마다 이전 파일이 자동으로 백업되므로(저장 백업과 복원) 실수해도 되돌릴 수 있습니다.

Edits reach disk only when you press Save XML for that workspace. Until then they live in the browser, and moving to another workspace prompts Save / Discard / Cancel. "Discard" reloads the file from the server, undoing everything since the last save. The same protection applies when you switch folders or close the page, and the Events workspace is included. Every save backs up the previous file first (Backups & restore), so mistakes are recoverable.

Tip. 각 워크스페이스에서는 그 워크스페이스가 쓰는 지도 오브젝트만 클릭에 반응합니다. 예를 들어 OD Matrix에서는 링크만 클릭되고 노드·커넥션은 반응하지 않습니다. 전체 표는 FAQ에 있습니다.
Tip. Each workspace only responds to the map objects it actually uses — in OD Matrix, for instance, links are clickable but nodes and connections are not. The full table is in the FAQ.

설치와 첫 실행Install and first run

  1. NextSIM 을 설치하고 서버를 띄웁니다 — 방법은 설치 가이드를 보세요 (소스 저장소라면 루트에서 ./start_visualizer.sh).
  2. 브라우저에서 http://localhost:8000/editor 를 엽니다. 시뮬레이션 결과 재생용 Visualizer는 /visualizer 입니다.
  3. 상단바의 Inputs 버튼을 눌러 Folder 목록에서 네트워크 폴더를 선택합니다. SimulationInput/datasets/ 아래의 network_xml_* 폴더들이 자동으로 나열됩니다.
  4. 폴더를 선택하면 지도에 네트워크가 그려지고, 각 워크스페이스가 해당 파일을 읽어옵니다.
  1. Install NextSIM and start its server — see the installation guide (from a source checkout, run ./start_visualizer.sh at the root).
  2. Open http://localhost:8000/editor. The Visualizer, for replaying results, is at /visualizer.
  3. Click Inputs in the top bar and choose a network folder under Folder — every network_xml_* folder under SimulationInput/datasets/ is listed automatically.
  4. Selecting a folder draws the network and loads each workspace's file.

새 네트워크 폴더 만들기Creating a new network folder

Inputs → New network folder를 누르고 이름을 입력하면 빈 템플릿 파일 세트가 들어 있는 폴더가 생성됩니다. 빈 지도에서 Network 워크스페이스로 도로를 그리기 시작하면 됩니다. 실제 한국 도로망에서 시작하려면 표준노드링크 가져오기를 쓰는 편이 훨씬 빠릅니다.

Inputs → New network folder, give it a name, and you get a folder with a set of empty template files — start drawing roads in the Network workspace on the blank map. To start from a real Korean road network, importing standard node-link data is far faster.

주의. 저장하지 않은 변경이 있는 상태로 페이지를 닫거나 새로고침하면 브라우저가 한 번 더 확인을 요청합니다. 폴더를 바꿀 때도 마찬가지입니다.
Note. Closing or reloading the page with unsaved changes triggers a browser confirmation, as does switching folders.

지도 조작 공통 기능Shared map controls

화면 이동과 확대Pan and zoom

  • 확대/축소 — 마우스 휠 (커서 위치 기준)
  • 화면 이동(팬) — 마우스 가운데 버튼을 누른 채 드래그. 좌클릭 드래그는 워크스페이스별 편집 동작(박스 선택 등)에 쓰입니다.
  • 미니맵 — 좌측 하단의 개요 지도. 현재 화면 위치가 사각형으로 표시되고, 미니맵을 클릭·드래그하면 그 지점으로 이동합니다. ▾ 버튼으로 접을 수 있습니다.
  • 축척 막대 — 좌측 하단에 현재 배율 기준 거리가 표시됩니다.
  • Zoom — mouse wheel, centred on the cursor.
  • Pan — drag with the middle mouse button. Left-drag is reserved for per-workspace editing (box select and so on).
  • Minimap — the overview at bottom left marks the current view with a rectangle; click or drag it to jump. Collapse with ▾.
  • Scale bar — bottom left, in the current zoom's units.

전역 검색Global search Ctrl+K

노드·링크·정류장·PT 노선·철도역·철도노선을 ID나 이름으로 찾습니다. 결과를 선택하면 해당 워크스페이스로 전환되고 지도가 그 위치로 이동하며 객체가 선택됩니다. ↑↓로 이동, Enter로 확정, Esc로 닫기.

Finds nodes, links, stations, transit lines, rail stations, and rail lines by ID or name. Choosing a result switches to the owning workspace, moves the map there, and selects the object. ↑↓ to move, Enter to confirm, Esc to close.

거리 측정Measuring distance

좌측 하단 📏 Measure 버튼을 켜면 지도 클릭이 측정점 추가로 바뀝니다. 점을 이어 찍으면 총 거리(m/km)가 표시됩니다. 우클릭은 마지막 점 삭제, Esc 또는 버튼 재클릭으로 종료합니다. 모든 워크스페이스에서 쓸 수 있습니다.

Turning on 📏 Measure at bottom left makes map clicks add measuring points; the running total (m/km) is displayed. Right-click removes the last point; Esc or clicking the button again exits. Available in every workspace.

표시 옵션Display options

상단바 우측의 Display 버튼을 누르면 표시 옵션 패널이 열립니다: Node IDs / Link IDs 라벨, Rail(철도 레이어) 표시, 그리고 캔버스 배경색을 바꿀 수 있습니다. ID 라벨은 화면에 보이는 것만 그리며, 너무 축소해 라벨이 600개를 넘으면 표시를 보류합니다 — 확대하면 다시 나타납니다.

The Display button at the right of the top bar opens the display panel: Node IDs / Link IDs labels, the Rail layer, and the canvas background color. Only on-screen ID labels are drawn, and past about 600 they are withheld until you zoom in.

위성 배경Satellite basemap

같은 Display 패널의 Satellite basemap 에서 네트워크 아래에 위성/항공사진을 깔 수 있습니다. 실제 도로 위에 링크를 그리거나 노드 위치를 맞출 때 씁니다.

The Satellite basemap group in the same Display panel puts satellite or aerial imagery under the network — for drawing links over real roads or lining nodes up with them.

  • Esri Satellite — 키 없이 바로 쓸 수 있는 전 세계 위성영상.
  • VWorld Aerial — 국내 최고 해상도 항공영상. vworld.kr 에서 무료 인증키를 발급받아(사용 도메인에 접속 주소 등록) Key 칸에 넣으면 됩니다.
  • Opacity — 배경이 진하면 도로 폴리곤이 묻히므로 슬라이더로 조절합니다.
  • Esri Satellite — worldwide imagery, no key required.
  • VWorld Aerial — the highest-resolution aerial imagery for Korea. Get a free key at vworld.kr (register the address you serve from) and paste it into the Key field.
  • Opacity — dial the imagery back so the road polygons stay readable.

네트워크 좌표는 원점이 bbox 남서 모서리인 국소 미터 좌표라 그 자체로는 지구상 위치를 알 수 없습니다. 그래서 배경을 깔려면 좌표 정합(georeference)이 필요하고, 에디터가 아래 순서로 자동 탐색합니다 — 결과는 패널 아래 상태줄에 표시됩니다.

Network coordinates are local metric with the origin at the bounding box's south-west corner, so they carry no earth position on their own. A georeference is therefore needed before imagery can line up, and the editor looks for one in this order — the result is reported in the status line under the panel.

  1. 네트워크 폴더의 basemap.json (직접 정합해 저장한 값)
  2. osm_import.json — OSM 임포트 네트워크는 임포터와 같은 투영이라 정확히 일치
  3. network.xml 노드에 남은 osm_lat/osm_lon 태그
  4. nodelink_import.json — 표준노드링크(EPSG:5186) 원점을 위경도로 환산
  1. basemap.json in the network folder — an alignment you saved yourself.
  2. osm_import.json — OSM-imported networks share the importer's projection, so this is exact.
  3. osm_lat/osm_lon tags left on nodes in network.xml.
  4. nodelink_import.json — the standard node-link origin (EPSG:5186) converted to lat/lon.

넷 다 없는 네트워크(직접 만든 network.xml 등)는 Center 칸에 네트워크 중심의 위도, 경도를 넣고 Place 를 누른 뒤, Align 모드에서 맞춥니다 — 드래그는 이동, Alt+드래그는 회전, Shift+드래그는 축척입니다. 움직이는 것은 배경이고 network.xml 은 건드리지 않습니다. Save 를 누르면 네트워크 폴더의 basemap.json 에 저장돼 다음에 열 때 그대로 복원됩니다.

For a network with none of those (a hand-built network.xml, say), type the network centre's latitude, longitude into Center, press Place, then fine-tune in Align mode — drag to move, Alt+drag to rotate, Shift+drag to scale. You are moving the imagery; network.xml is never touched. Save writes basemap.json into the network folder so it is restored next time.

Tip. 제공자·불투명도·인증키는 브라우저에 저장되어 네트워크를 바꿔도 유지되고, 정합값은 네트워크의 성질이라 폴더마다 따로 보관됩니다.
Tip. Provider, opacity, and key live in the browser and survive a folder change; the alignment is a property of the network, so it is stored per folder.

실행 취소Undo

모든 워크스페이스에서 Ctrl+Z 실행 취소, Ctrl+Y 다시 실행이 동작합니다. 히스토리는 워크스페이스별로 따로 관리됩니다 (저장 이후의 변경도 저장 전까지는 되돌릴 수 있습니다).

Ctrl+Z undoes and Ctrl+Y redoes in every workspace. History is kept per workspace.

Workspace Network

담당 파일:File: network.xml

도로망의 노드(교차로)·링크(도로)·차로·커넥션(교차로 내 회전 연결)을 편집합니다. 좌측 세로 도구 레일에서 편집 모드를 고르고 지도에서 직접 작업합니다. 상단 중앙의 Network tools 패널에는 일괄 편집·병합·복사·실행취소·검증이, 우측 패널의 표(Nodes / Links / Connections / Lanes 탭)에는 수치 속성 편집이 있습니다.

Edits the road network's nodes (intersections), links (roads), lanes, and connections (turning movements inside an intersection). Pick an edit mode from the vertical tool rail on the left and work directly on the map. The Network tools panel at top centre holds bulk edit, merge, copy, undo, and validation; the right-hand panel's tables (Nodes / Links / Connections / Lanes) hold numeric attribute editing.

커넥션과 터미널 노드Connections and terminal nodes

노드를 선택하고 Generate connections를 누르면 연결된 링크들의 기하로부터 회전 방향(좌/직/우/유턴)을 추정해 커넥션을 자동 생성합니다. 노드나 링크를 옮기면 관련 커넥션은 자동으로 다시 계산됩니다.

Select a node and press Generate connections to infer turn directions (left/through/right/U-turn) from the attached links' geometry and create the connections. Moving a node or link recomputes the affected connections automatically.

어느 노드에도 연결되지 않은 링크 끝점은 저장할 때 자동으로 터미널(terminal) 노드가 만들어져 연결됩니다. 터미널 노드는 차량이 네트워크에 들어오고 나가는 지점으로, OD Matrix의 기·종점이 됩니다. 터미널의 포트 방향이 곧 역할을 정합니다 — out 포트면 출발지(source), in 포트면 도착지(sink).

Link endpoints not attached to any node get a terminal node created automatically on save. Terminal nodes are where vehicles enter and leave the network and serve as the origins and destinations in the OD Matrix. The port direction decides the role: an out port makes it a source, an in port a sink.

Network 상충 · 통행우선권 편집기Conflict / Right-of-Way editor

도구 레일의 Conflict(W)를 켜고 교차로 노드를 클릭하면 전용 패널이 열립니다. 편집 중에는 해당 교차로 외의 지도가 흐려져 대상에 집중할 수 있습니다. 결과는 network.xml 의 노드 안에 <conflict> 요소로 저장되며, 엔진은 이 요소를 무시하므로 기존 시뮬레이션에 영향을 주지 않습니다.

Enable Conflict (W) on the tool rail and click an intersection node to open its panel. While editing, the rest of the map dims so you can focus on that junction. Results are stored as <conflict> elements inside the node in network.xml; the engine ignores them, so existing simulations are unaffected.

  • 이동류(movement) — 같은 (진입 링크 → 진출 링크) 조합의 커넥션 묶음입니다. 별도 데이터가 아니라 기존 커넥션에서 파생되며, 신호의 turn 과 1:1로 대응합니다. 회전 종류(직진/좌/우/유턴)는 기하로 자동 분류되고 필요하면 직접 바꿀 수 있습니다.
  • Detect — 이동류 간 상충을 자동 판정합니다: Crossing(교차 — 동시 녹색 불가), Merging(합류 — 양보), Diverging(분기 — 신호 상충 아님).
  • Auto — 도로 등급·회전 종류로 통행우선권(우선순위, 정지/양보 의무)을 일괄 부여합니다.
  • Validate — 우선순위 모순(순환 등)을 검사합니다.
  • Movements — the group of connections sharing one (from-link → to-link) pair. They are derived from the existing connections rather than stored separately, and correspond one-to-one with a signal turn. The turn kind (through/left/right/U) is classified from geometry and can be overridden.
  • Detect — classifies conflicts between movements: Crossing (cannot be green together), Merging (yield), and Diverging (not a signal conflict).
  • Auto — assigns right-of-way (priority, stop/yield obligations) from road class and turn kind.
  • Validate — checks for contradictory priorities such as cycles.
Tip. 상충 판정은 Signal 워크스페이스의 Auto phases 가 그대로 사용합니다 — 교차 상충이 없는 이동류들이 한 현시로 묶입니다.
Tip. The Signal workspace's Auto phases reuses these conflicts directly — movements without a crossing conflict are grouped into one phase.

차종Vehicle types

엔진이 OD로 표현할 수 있는 차종은 nv(일반차), av(자율차), tr(화물차), cav(연결 자율차) 넷이며, 각각 odmatrix.xml 안의 별도 매트릭스입니다. Vehicle type 드롭다운은 그중 이 프로젝트의 parameter_xml/vehicletypes.xml 에 실제로 정의된 차종만 보여줍니다 — 정의되지 않은 차종으로 수요를 만들면 엔진이 차종 조회에 실패하기 때문입니다.

The engine can express four vehicle types in an OD matrix — nv (normal), av (autonomous), tr (truck), cav (connected autonomous) — each its own matrix inside odmatrix.xml. The Vehicle type dropdown lists only those actually defined in this project's parameter_xml/vehicletypes.xml, because demand for an undefined type would make the engine fail its type lookup.

생성 규칙은 다음과 같습니다:

The generation rules are:

  • 녹색현시는 교차 상충이 없는 이동류들의 묶음입니다. 좌회전은 대향 직진과 교차하므로 자동으로 분리되어 보호좌회전이 됩니다.
  • 우회전은 신호 대상에서 빠져 RTOR 타입으로 모든 현시에 녹색으로 포함됩니다.
  • 녹색현시마다 뒤에 황색현시가 하나씩 삽입됩니다. 예를 들어 4현시라면 signal.xml 상 현시는 8개가 됩니다.
  • 현시 시간은 임계 차로 수에 비례해 배분되고, 최소녹색시간으로 보정됩니다.
  • A green phase is a group of movements with no crossing conflict. Left turns cross the opposing through movement, so they separate out on their own — protected left turns.
  • Right turns are excluded from the signal and emitted as RTOR turns that stay green in every phase.
  • Each green phase is followed by one yellow phase, so a 4-phase plan becomes 8 phases in signal.xml.
  • Durations are split in proportion to critical lane count, then corrected against the minimum green time.

주의. 버스 노선은 현재 배차 간격(Interval) 기반으로만 운행됩니다. 시각표 기반 버스 운행은 엔진 확장이 필요한 항목입니다.

표준노드링크 가져오기Importing standard node-link data

국가표준노드링크(ITS 표준 노드·링크 체계)의 SHP 파일에서 원하는 영역만 잘라 NextSIM 네트워크를 자동 생성합니다. OSM보다 국내 도로망 정확도가 높아 한국 지역 네트워크의 출발점으로 권장합니다.

  1. ITS 국가교통정보센터(its.go.kr)에서 표준노드링크 SHP를 내려받아 SimulationInput/nodelink/<이름>/ 폴더에 MOCT_NODE.shp/.dbf, MOCT_LINK.shp/.dbf 4개 파일을 둡니다.
  2. 상단바 Inputs → Import nodelink (SHP) → SHP set에서 폴더를 선택하면 노드·링크 수와 전체 범위가 표시됩니다.
  3. Extent에 잘라낼 영역의 좌표(EPSG:5186, m)를 입력하거나 Use full extent로 전체를 지정합니다.
  4. Preview로 실제 생성 없이 포함될 노드·링크 수를 확인하고, 폴더 이름을 정한 뒤 Import — 새 네트워크 폴더가 만들어지고 바로 편집을 시작할 수 있습니다.

가져오는 동안 차로 수(LANES)·제한속도(MAX_SPD)·도로명 등의 속성이 매핑되고, 차로 기하와 교차로 커넥션은 Network 편집기와 같은 규칙으로 자동 생성됩니다.

Tip. 시·도 단위 전체 SHP에서도 bbox로 잘라내면 수 초 안에 끝납니다. 우선 작은 영역으로 Preview 해보고 범위를 넓혀 가세요.

  2. Inputs → Import nodelink (SHP), then pick the folder under SHP set — the node and link counts and the full extent are shown.
  3. Enter the area to cut out under Extent (EPSG:5186, metres), or press Use full extent.
  4. Preview reports how many nodes and links would be included without creating anything; then name the folder and press Import — a new network folder is created and ready to edit.

During the import, attributes such as lane count (LANES), speed limit (MAX_SPD), and road name are mapped over, and lane geometry and intersection connections are generated by the same rules the Network editor uses.

Tip. Even a province-wide SHP set cuts down in seconds once you give it a bbox. Preview a small area first, then widen it.

Because U-turns are never created, a dead-end turning point — or two ways drawn facing each other, where every movement would be a U-turn — has its link end split off as a terminal node. Left as is, vehicles that enter cannot leave, and an exit link with no connections at all crashes the engine with std::out_of_range during intersection setup.
Coordinate systems. The importer converts to metres with a local transverse Mercator and puts the origin at the bbox's south-west corner. Importing twice with different bboxes gives different origins, so to widen the area re-import from scratch with the larger bbox.
Tip. Public Overpass servers return 502/504 when busy. The importer rotates through mirrors and retries, but if it keeps failing, wait a little or download an .osm from BBBike into SimulationInput/osm/ and use file mode. OSM data is ODbL 1.0; attribution is recorded in the folder's osm_import.json.

저장 백업과 복원Backups and restore

어떤 워크스페이스든 저장할 때마다 덮어쓰기 직전의 파일이 폴더 안 .backups/에 자동 보관됩니다 (파일별 최근 10개, 내용이 같으면 중복 저장 안 함).

  1. 상단바 Inputs → Backups를 누르면 파일별 백업 목록이 시각·크기와 함께 표시됩니다. 현재 파일과 내용이 같은 백업은 "= current"로 표시됩니다.
  2. Diff — 그 백업과 현재 파일의 차이(추가/삭제 줄 수와 상세 diff)를 미리 봅니다.
  3. Restore — 해당 시점으로 되돌립니다. 복원 직전의 현재 파일도 백업으로 남으므로 복원 자체를 다시 되돌릴 수 있습니다. 복원 후 폴더가 자동으로 다시 로드됩니다.

Every save, in any workspace, first copies the file it is about to overwrite into .backups/ inside the folder (the 10 most recent per file; identical content is not stored twice).

  1. Inputs → Backups lists the backups per file with time and size. A backup whose content matches the current file is marked "= current".
  2. Diff — preview what changed between that backup and the current file (added and removed line counts, plus the detailed diff).
  3. Restore — roll back to that point. The file as it stands is backed up first, so the restore itself can be undone. The folder reloads afterwards.

FAQ · 문제 해결FAQ & troubleshooting

이 워크스페이스에서 뭐가 클릭되나요?What is clickable in each workspace?

워크스페이스마다 그곳에서 쓰는 오브젝트만 클릭·호버에 반응합니다. 다른 오브젝트를 편집하려면 해당 워크스페이스로 이동하세요.

Each workspace responds only to the objects it uses. To edit something else, switch to the workspace that owns it.

같은 워크스페이스 안에서도 활성 도구가 대상을 더 좁힙니다 — Network 의 Conflict(W) 는 교차로 노드만 받고, OD 의 source 선택 모드 에서는 링크 클릭이 OD 행 추가가 아니라 진입점 토글로 동작합니다.

The active tool narrows it further within a workspace — Network's Conflict (W) accepts intersection nodes only, and in OD's source pick mode a link click toggles an entry point instead of adding an OD row.

큰 네트워크를 열면 느리지 않나요?Is a large network slow to work with?

네트워크는 규모와 무관하게 항상 캔버스로 그려집니다. 뷰포트 컬링과 배율별 LOD 를 쓰기 때문에 그리는 양이 화면 크기에만 비례하고, 수만 링크 규모까지 부드럽게 동작합니다. (예전에는 링크 800개를 기준으로 SVG/캔버스를 갈랐지만, 그 아래 규모에서도 DOM 요소가 수천 개라 버벅여서 기준을 없앴습니다.)

The network is always drawn on canvas, regardless of size. With viewport culling and zoom-based level of detail, the amount drawn scales with the screen rather than the network, and it stays smooth into the tens of thousands of links. (There used to be an 800-link SVG/canvas threshold, but even below it a few thousand DOM elements stuttered, so the threshold was removed.)

렌더 차이를 확인해야 할 때만 브라우저 콘솔에서 localStorage.setItem('nextsim-network-canvas','off') 로 예전 SVG 경로를 켤 수 있습니다. 'on' 을 넣는 것은 이제 의미가 없습니다 — 기본이 이미 캔버스입니다.

For debugging a rendering difference you can force the old SVG path from the console with localStorage.setItem('nextsim-network-canvas','off'). Setting it to 'on' does nothing now — canvas is already the default.

편집할 때 화면이 깜빡이지 않나요?Does the map flicker while editing?

아닙니다. 예전에는 링크·노드를 고칠 때마다 렌더러를 통째로 다시 만들어 화면이 잠깐 비었지만, 지금은 카메라를 유지한 채 제자리에서 갱신합니다 — 캔버스는 기존 그림을 그대로 둔 채 한 프레임에 새 그림으로 덮고, 줌·위성 배경·이벤트 바인딩은 살아 있습니다. 결과적으로 큰 네트워크에서 편집 반영도 빨라졌습니다.

No. Editing used to rebuild the whole renderer, briefly blanking the map; now it refreshes in place with the camera intact — the canvas keeps its current pixels until the new frame overwrites them, and the zoom, basemap, and event bindings stay alive. Edits also apply faster on large networks as a result.

저장·오류 메시지는 어디에 뜨나요?Where do save and error messages appear?

모두 화면 우측 상단 토스트로 뜹니다. 패널 안에는 실시간 상태 문구를 표시하지 않으며, 같은 메시지가 반복되면 한 번만 보여줍니다. 다만 위성 배경의 정합 상태는 예외로 Display 패널 안에 남아 있습니다.

All of them as a toast in the top-right corner. The panels no longer carry a live status line, and repeats of the same message are shown once. The one exception is the basemap georeference status, which stays inside the Display panel.

에디터에 없는 XML 속성은 저장하면 사라지나요?Are XML attributes the editor doesn't show lost on save?

아니요. qmax, wave_spd처럼 에디터 화면에 노출되지 않는 속성도 저장 시 원본 그대로 보존됩니다.

No. Attributes that never appear in the UI — qmax, wave_spd, and the like — are preserved verbatim on save.

워크스페이스끼리 참조가 어긋나면?What if references between workspaces break?

저장할 때 다른 워크스페이스가 참조하는 ID(예: PT 노선이 참조하는 링크, 신호가 참조하는 노드)가 사라지면 경고 알림으로 알려줍니다. 삭제·분할 후에는 관련 워크스페이스를 한 번 확인하는 습관을 권합니다.

Saving warns you when an ID another workspace references disappears — a link a PT line uses, a node a signal points at. After deleting or splitting, it is worth checking the related workspaces once.

지도가 이동이 안 돼요 / 클릭이 이상해요The map won't pan, or clicks behave oddly

  • 화면 이동은 가운데 버튼 드래그입니다 — 좌클릭 드래그는 편집 동작(박스 선택 등)에 배정되어 있습니다.
  • 측정 도구(📏)가 켜져 있으면 모든 클릭이 측정점 추가로 동작합니다. Esc로 끄세요.
  • Network의 편집 모드가 걸려 있으면 Esc로 해제 후 Select(V)로 돌아오세요.
  • OD 에서 source 선택 모드가 켜져 있으면 링크 클릭이 진입점 토글로 동작합니다 — 아래쪽 바의 Done 또는 Esc로 끝내세요.
  • Pan with the middle button — left-drag is bound to editing (box select and so on).
  • With the measure tool (📏) on, every click adds a measuring point. Esc turns it off.
  • If a Network edit mode is active, press Esc and return to Select (V).
  • In OD, source pick mode makes link clicks toggle entry points — finish it with Done in the bottom bar or Esc.

편집 결과로 시뮬레이션을 돌리려면?How do I run a simulation with my edits?

Save every workspace, go to /visualizer, select this network folder and a scenario, and press Run Selected Network. For replaying and analysing the result, see the Visualizer guide.
