NextSIM Edit 모드 사용자 가이드NextSIM Edit Mode User Guide

NextSIM 화면의 Edit 모드에서는 NextSIM 하이브리드 교통 시뮬레이터의 입력 데이터를 브라우저에서 시각적으로 만들고 편집할 수 있습니다. 도로 네트워크부터 수요(OD), 신호, 대중교통, 이벤트, 시나리오까지, 시뮬레이션에 필요한 모든 입력 파일을 하나의 지도 위에서 다룹니다. 시뮬레이션 실행과 결과 재생은 같은 화면의 Run 모드가 맡습니다.

Edit mode of the NextSIM page is where you build and edit the input data of the NextSIM hybrid traffic simulator in the browser. Road network, demand (OD), signals, transit, events, scenarios — every input file a simulation needs, all on one map. Running simulations and replaying results is the job of Run mode on the same page.

Edit 모드 소개What Edit mode is

Edit 모드는 네트워크 폴더 단위로 동작합니다. 하나의 네트워크 폴더는 시뮬레이션 한 세트에 필요한 입력 파일 묶음이고, Edit 모드의 각 워크스페이스가 그중 한 파일을 담당합니다. 모든 워크스페이스는 같은 지도(네트워크 캔버스)를 공유합니다.

Edit mode works one network folder at a time. A network folder is the bundle of input files one simulation needs, and each workspace in Edit mode owns one of those files. Every workspace shares the same map canvas.

NextSIM 화면에는 Run 모드(실행·결과 재생)와 Edit 모드(입력 편집)가 있고, 두 모드가 동시에 켜지지는 않습니다. 상단바의 Run | Edit 전환으로 두 모드를 오가며, 두 모드는 같은 네트워크 폴더를 엽니다. 전환할 때 적용되는 규칙은 Run 모드로 전환을 참고하세요.

The NextSIM page has two modes that are never on at the same time: Run mode (running and replaying) and Edit mode (editing inputs). The Run | Edit switch in the top bar moves between them, and both work on the same network folder — see Switching to Run mode for what happens on the way.

화면 구성Layout

  • 상단바: 좌측에는 NextSIM 로고, Run | Edit 모드 전환과 워크스페이스 버튼 줄이 있습니다. 버튼은 도로망(Network) | 운영(Signal · Mode · Infra) | 수요(OD · Pax) | 대중교통(Station · PT) | 시나리오(Scenario · Events) 순으로 묶여 있고, 좁은 화면(1440px 이하)에서는 아이콘만 남습니다(이름은 툴팁). 우측 끝에는 저장 상태 · Revert · Save all · Save(현재 워크스페이스용) · Setup · 도움말(물음표, 이 설명서를 엽니다)이 모여 있습니다. Setup을 누르면 상단바가 Network(현재 네트워크 이름 표시. 누르면 Network 창이 열려 네트워크 선택·추가·패키지 내보내기·다른 이름으로 저장·백업을 할 수 있습니다)과 Display(표시 옵션) 줄로 바뀌고, X 나 Esc로 돌아옵니다.
  • 도구 패널: 상단바 바로 아래 중앙에 떠 있는 플로팅 패널로, 현재 워크스페이스의 편집 버튼(Add/Reload 등)이 여기에 모여 있습니다. 워크스페이스를 바꾸면 패널 내용도 함께 바뀝니다.
  • 지도(캔버스): 편집할 네트워크가 그려지는 중앙 영역입니다. Network 워크스페이스에서는 좌측에 세로 도구 레일이 추가로 나타납니다.
  • 에디터 패널: 속성 표와 인스펙터가 담긴 패널입니다. 워크스페이스에 따라 우측에 도킹된 패널(Network·Signal·Station 등) 또는 지도를 덮는 반투명 오버레이(OD·Scenario)로 열립니다.
  • Top bar — on the left, the NextSIM logo, the Run | Edit mode switch and the workspace buttons, grouped as road network (Network) | operations (Signal · Mode · Infra) | demand (OD · Pax) | transit (Station · PT) | scenario (Scenario · Events); on narrow screens (1440px and below) only the icons remain, with names in tooltips. Right-aligned at the far end: the save state, Revert, Save all, Save (for the current workspace), Setup and help (question mark, opens this guide). Setup turns the bar into Network (shows the current network; it opens the Network dialog: selecting, adding, exporting as a package, save as, backups) and Display; X or Esc returns.
  • Tools panel — a floating panel centred just under the top bar holding the current workspace's edit buttons (Add, Reload, and so on). Its contents change with the workspace.
  • Map (canvas) — the central area where the network is drawn. The Network workspace adds a vertical tool rail on the left.
  • Editor panel — the attribute tables and inspector. Depending on the workspace it docks on the right (Network, Signal, Station …) or opens as a translucent overlay across the map (OD, Scenario).
상태 메시지는 팝업으로. 저장 완료·검증 경고·오류 같은 실시간 피드백은 패널 안이 아니라 화면 우측 상단 토스트로 표시됩니다. 같은 메시지가 연달아 발생하면 한 번만 표시됩니다.

저장 모델How saving works

편집 내용은 우측 상단의 Save(Ctrl+S)를 눌러야 그 워크스페이스의 파일에 기록됩니다(버튼에 마우스를 올리면 어떤 파일인지 보입니다). 저장하기 전에는 브라우저 안에만 남아 있고, 다른 워크스페이스로 옮겨 가도 그대로 유지됩니다. 저장하지 않은 워크스페이스는 상단 버튼에 주황색 점이 붙고, 지금 워크스페이스에 미저장 편집이 있으면 Save 옆에 Unsaved changes가, 저장한 뒤에는 Saved 14:02처럼 저장 시각이 보입니다.

  • Save all (N)(Ctrl+Shift+S): 다른 워크스페이스에도 미저장 편집이 있으면 나타나며, 모두 저장합니다(Network를 먼저 저장).
  • Revert: 지금 워크스페이스의 미저장 편집을 버리고 파일을 다시 불러옵니다.
  • 되돌리기(Ctrl+Z)로 마지막 저장 상태까지 돌아오면 미저장 표시가 사라집니다.
  • 네트워크를 바꾸거나, Run 모드로 넘어가거나, 페이지를 닫을 때는 저장하지 않은 워크스페이스를 모아 묻습니다 (Run 모드로 전환). Events 워크스페이스도 포함됩니다.

저장할 때마다 이전 파일이 자동으로 백업되므로(저장 백업과 복원) 실수해도 되돌릴 수 있습니다. 주소창에는 지금 워크스페이스가 ?tab=으로 남아서, 새로고침해도 같은 탭으로 열립니다.

Edits reach disk only when you press Save (Ctrl+S) for that workspace (hover the button to see which files). Until then they live in the browser and stay when you move to another workspace. Workspaces with unsaved edits get an orange dot on their top-bar button; next to Save you see Unsaved changes for the current workspace, or the save time (Saved 14:02) after saving.

  • Save all (N) (Ctrl+Shift+S) appears when other workspaces have unsaved edits too and saves them all (Network first).
  • Revert discards the current workspace's unsaved edits and reloads its files.
  • Undoing (Ctrl+Z) back to the last saved state clears the unsaved mark.
  • Switching networks, switching to Run mode or closing the page asks once about every unsaved workspace (Switching to Run mode). The Events workspace is included.

Every save backs up the previous file first (Backups & restore), so mistakes are recoverable. The address bar keeps the current workspace as ?tab=, so a reload reopens the same tab.

Tip. 각 워크스페이스에서는 그 워크스페이스가 쓰는 지도 오브젝트만 클릭에 반응합니다. 예를 들어 OD Matrix에서는 링크만 클릭되고 노드·커넥션은 반응하지 않습니다. 전체 표는 FAQ에 있습니다.
Tip. Each workspace only responds to the map objects it actually uses — in OD Matrix, for instance, links are clickable but nodes and connections are not. The full table is in the FAQ.

설치와 첫 실행Install and first run

  1. NextSIM을 설치하고 서버를 실행합니다. 방법은 설치 가이드를 참고하세요 (소스 저장소라면 루트에서 ./start_visualizer.sh를 실행합니다).
  2. 브라우저에서 http://localhost:8000/nextsim/?mode=edit를 엽니다. /nextsim/은 Run 모드로 열리므로, 상단바의 Edit을 눌러 전환해도 됩니다. 홈 화면(/)의 네트워크 카드에서 편집을 누르면 그 네트워크가 Edit 모드로 열립니다. 특정 네트워크를 바로 열려면 /nextsim/?mode=edit&folder=SimulationInput/networks/<이름> 처럼 주소를 입력합니다. 예전 주소인 /editor/로 접속하면 /nextsim/?mode=edit로 이동하며, 쿼리는 그대로 유지됩니다.
  3. 상단바 Setup → Network(처음에는 Select network)를 눌러 Network 창의 목록에서 네트워크 폴더를 선택합니다. SimulationInput/networks/ 아래의 네트워크 폴더들이 이름으로 나열됩니다.
  4. 폴더를 선택하면 지도에 네트워크가 그려지고, 각 워크스페이스가 해당 파일을 읽어옵니다.
  1. Install NextSIM and start its server — see the installation guide (from a source checkout, run ./start_visualizer.sh at the root).
  2. Open http://localhost:8000/nextsim/?mode=edit. Plain /nextsim/ opens in Run mode; click Edit in the top bar to switch. On the home page (/), a network card's 편집 (Edit) button opens that network in Edit mode. To open a given network directly, use /nextsim/?mode=edit&folder=SimulationInput/networks/<name>. The old address /editor/ redirects to /nextsim/?mode=edit, keeping its query.
  3. Click Setup → Network in the top bar (it reads Select network until you pick one) and choose a network folder from the list in the Network dialog — every network folder under SimulationInput/networks/ is listed by name.
  4. Selecting a folder draws the network and loads each workspace's file.

새 네트워크 추가하기Adding a network

Network → Add network를 누르면(네트워크를 고르기 전 빈 화면의 Add network 버튼도 같습니다) 네트워크를 만드는 방법을 고르는 Add a network 창이 뜹니다. Run 모드에서 누르면 먼저 Edit 모드로 전환되며, 시뮬레이션이 실행 중이거나 결과가 열려 있으면 전환 경고가 먼저 뜹니다.

  • New network folder: 이름을 입력하면 빈 템플릿 파일 세트(기본 parameter_xml/ 포함)가 든 폴더가 만들어집니다. 빈 지도에서 Network 워크스페이스로 도로를 그리기 시작하면 됩니다.
  • Import OpenStreetMap: 위경도 bbox로 지정한 영역의 OSM 도로망을 가져옵니다 (OpenStreetMap 가져오기).
  • Import Korean node-link: 국가표준노드링크 SHP에서 영역을 잘라 네트워크를 만듭니다 (표준노드링크 가져오기). 실제 한국 도로망에서 시작하려면 이쪽이 훨씬 빠릅니다.
  • Random network: 간선·곡선·제거 블록이 섞인 도시형 격자망을 만듭니다. 격자 크기·블록 길이· 흔들림·곡률·일방통행 비율과 Entry roads every n-th edge road(가장자리 도로 n개마다 바깥으로 나가는 진출입로를 만들며, 그 끝이 수요가 드나드는 terminal 노드가 됩니다. 0이면 만들지 않습니다)를 정합니다. 같은 seed와 설정이면 항상 같은 망이 만들어지며, 수요는 망을 만든 뒤 OD Matrix 워크스페이스에서 입력합니다.
  • Import network package: 전달받은 네트워크 패키지(.zip)로 네트워크를 추가합니다 (패키지와 다른 이름으로 저장).

새로 추가한 네트워크를 실행해 보려면 Edit 모드에서 저장한 뒤 Run 모드로 전환해 실행합니다.

Network → Add network (or the Add network button on the empty screen shown before a network is picked) opens the Add a network chooser. Pressed in Run mode, it switches to Edit mode first — with the switch warning if a run is in progress or a result is open.

  • New network folder — give it a name and you get a folder with a set of empty template files (default parameter_xml/ included); start drawing roads in the Network workspace on the blank map.
  • Import OpenStreetMap — road network from OSM for a lat/lon bbox (Importing OpenStreetMap).
  • Import Korean node-link — cut an area out of the national standard node-link SHP set (Importing standard node-link data). To start from a real Korean road network, this is far faster.
  • Random network — a city-like grid with arterials, curves, and removed blocks. You set the grid size, block length, jitter, curvature, one-way share, and Entry roads every n-th edge road (a short road leaving the area on every n-th edge road; its end becomes a terminal node where demand enters and leaves, 0 = none). The same seed and settings always give the same network; add demand afterwards in the OD Matrix workspace.
  • Import network package — add a network from a package file (.zip) you received (Packages & Save as).

To run a network you just added, save it in Edit mode, switch to Run mode, and run it there.

주의. 저장하지 않은 변경이 있는 상태로 페이지를 닫거나 새로고침하면 브라우저가 한 번 더 확인을 요청합니다. 폴더를 바꿀 때도 마찬가지입니다.
Note. Closing or reloading the page with unsaved changes triggers a browser confirmation, as does switching folders.

Run 모드로 전환Switching to Run mode

상단바의 Run을 누르면 같은 네트워크가 Run 모드로 열립니다. 저장하지 않은 변경 사항이 없으면 바로 전환되고, 있으면 해당 워크스페이스들을 나열한 Unsaved changes 창이 뜹니다.

Run in the top bar opens the same network in Run mode. With nothing unsaved it switches straight away; otherwise an Unsaved changes dialog lists the workspaces with unsaved edits.

  • Discard: 변경 사항을 버리고 전환합니다. Run 모드는 마지막으로 저장된 네트워크를 사용합니다.
  • Save & switch: 저장하지 않은 워크스페이스를 모두 저장한 뒤(Network를 가장 먼저 저장) 전환합니다. 하나라도 저장에 실패하면(검증 오류 등) Edit 모드에 남습니다. 해당 패널에 표시된 문제를 고친 뒤 다시 전환하세요.
  • 오른쪽 위의 X 또는 Esc: 창을 닫고 Edit 모드에 남습니다. 어디에서 저장하면 되는지 알려 주기 위해 현재 보이는 Save 버튼이 잠깐 깜빡입니다.
  • Discard — drop the changes and switch; Run mode uses the network as last saved.
  • Save & switch — save every unsaved workspace (Network first), then switch. If a save fails — a validation error, say — you stay in Edit mode; fix the problem shown in that panel and switch again.
  • X (top right) or Esc — close the dialog and stay in Edit mode. The visible Save button pulses briefly to show where to save.

모드를 바꿀 때마다 현재 네트워크 폴더를 서버에서 다시 읽으므로, Run 모드에는 Edit 모드에서 저장한 내용이 그대로 보입니다. 지도 위치(화면)는 전환해도 유지됩니다. 편집을 저장하고 Run 모드로 넘어가면 Your edits are saved. Run the simulation again to see their effect. 알림이 뜹니다. network.xml을 고쳤다면 편집 전에 만든 결과를 열 때 네트워크가 바뀌었다는 경고가 뜨므로 다시 실행하세요 (Run 모드 가이드).

Every mode switch reloads the current network folder from the server, so Run mode shows exactly what you saved in Edit mode, and the map position is kept.   • 링크 하나: ID, 시작·끝 노드, 길이(읽기 전용, 형상에서 계산), 커넥션 수를 보여 주고 Speed (km/h), Lane width (m), Lanes(−/+ 또는 숫자 입력), Road class, 차로별 Lane use와 Lane segments를 고칩니다. Lane width는 차로 하나의 폭이고, 그 아래의 Road width(읽기 전용)는 차로 폭 × 차로 수로 계산되어 network.xml의 링크 width로 저장됩니다. 차로 수를 바꾸면 차로 폭은 그대로이고 도로 폭이 늘거나 줄어듭니다. 차로 수나 차로 폭을 바꾸면 양 끝 노드의 커넥션이 새로 만들어집니다. 아래 버튼으로 양 끝 노드의 커넥션 생성(Generate connections), 형상 편집(Edit shape), 삭제를 합니다.
  • 노드 하나: 들어오는·나가는 링크 수와 커넥션 수를 보여 주고 노드 타입을 고칩니다. 터미널은 링크가 정확히 하나인 노드만 될 수 있습니다. 버튼으로 커넥션 생성, 상충 편집기 열기(Conflicts…), 삭제를 합니다.
  • 여러 링크: 값이 모두 같으면 그 값을, 다르면 mixed를 보여 줍니다. 값을 입력하면 선택한 링크 모두에 한 번에 적용됩니다(되돌리기도 한 번). Lane use는 맨 왼쪽·맨 오른쪽·모든 차로를 골라 일괄 지정합니다. Add reverse, Join, 삭제 버튼도 여기 있습니다.
  • 노드와 링크를 섞어 선택: 개수를 보여 주고, 링크 칸은 링크에만, 노드 타입은 노드에만 적용됩니다.
  • One link — shows the ID, from/to nodes, length (read-only, computed from the shape) and connection count, and edits Speed (km/h), Lane width (m), Lanes (−/+ or type a number), Road class, and per-lane Lane use and Lane segments. Lane width is the width of one lane; the read-only Road width under it is lane width × lanes and is saved as the link's width in network.xml. Changing the lane count keeps the lane width, so the road gets wider or narrower. Changing the lane count or lane width rebuilds the connections at both end nodes. The buttons generate connections at both end nodes, open Edit shape, or delete the link.
  • One node — shows the inbound/outbound link and connection counts and edits the node type. Only a node with exactly one link can become a terminal. The buttons generate connections, open the conflict editor (Conflicts…), or delete the node.
  • Several links — a field shows the shared value, or mixed when they differ. Typing a value applies it to every selected link at once (one undo step). Lane use offers leftmost, rightmost or all lanes in bulk. Add reverse, Join and Delete are here too.
  • Nodes and links together — shows the counts; link fields apply to the links and the node type to the nodes.

여러 링크·노드 한 번에 다루기Working on many objects at once

  • 일괄 편집: 링크 여러 개를 선택한 뒤 선택 인스펙터에서 Speed (km/h)·Lane width (m)·Lanes·Road class 값을 입력하면 선택한 링크 모두에 적용됩니다. Lane width는 링크마다 그 링크의 차로 수를 곱한 값이 도로 폭이 됩니다.
  • Merge nodes: 노드 여러 개를 선택해 하나의 교차로로 병합합니다 (N 키와 같습니다). 연결된 링크와 커넥션은 자동으로 재구성됩니다.
  • Join (J): 일렬로 이어진 링크들을 하나로 합칩니다. Split의 반대 동작으로, 중간 노드가 다른 곳에 쓰이지 않으면 함께 제거됩니다.
  • Add reverse (R): 선택한 링크의 역방향 링크를 자동으로 생성합니다. 우측통행을 기준으로 원본의 왼쪽에 도로 폭만큼 떨어져 나란히 배치되며, 이미 역방향 링크가 있으면 건너뜁니다.
  • Copy props / Paste props (Ctrl+Alt+C / V): 한 링크의 속성(차로 수·속도·폭·도로 유형·차로 통행제한 등)을 복사해 선택한 다른 링크들에 한 번에 적용합니다.
  • 복사·붙여넣기 (Ctrl+C / V): 선택한 노드·링크를 통째로 복제합니다. 복제본은 새 ID를 받고 원본에서 조금 떨어진 위치에 놓이며, 반복해서 붙여넣을 때마다 조금씩 더 떨어져 배치됩니다. 선택 범위 안에서 서로 이어진 연결만 함께 복사됩니다.
  • New junction…: 4지/3지 신호교차로 템플릿입니다. 접근로의 차로 수·길이·속도를 정하면 화면 중앙에 노드와 방향별 진입·진출 링크, 자동 커넥션이 생성되고, 원하면 기본 신호 플랜(Signal 워크스페이스에 추가됨)까지 만들어 줍니다.
  • Bulk edit — select several links and type Speed (km/h), Lane width (m), Lanes or Road class in the selection inspector; the value applies to every selected link. With Lane width, each link's road width becomes that lane width times its own lane count.
  • Merge nodes — merge several selected nodes into one intersection (same as N). Attached links and connections are rebuilt automatically.
  • Join (J) — merges a chain of consecutive links back into one. The inverse of Split; the intermediate node is removed too when nothing else uses it.
  • Add reverse (R) — creates opposite-direction links for the selection, placed one road-width to the left (right-hand traffic). Links that already have a reverse are skipped.
  • Copy props / Paste props (Ctrl+Alt+C / V) — copy one link's attributes (lane count, speed, width, road type, lane access restrictions) and apply them to every selected link at once.
  • Copy / paste objects (Ctrl+C / V) — duplicates the selected nodes and links with fresh IDs, offset from the original; pasting again offsets further. Only connections internal to the selection come along.
  • New junction… — a 4-way / 3-way signalized intersection template. Set approach lane count, length, and speed, and it generates a node with inbound/outbound links per direction plus connections at the map centre — optionally with a starter signal plan added to the Signal workspace.

차로 이용 구분: 버스 · 트램 · HOV 전용차로Lane use — bus, tram and HOV lanes

링크를 선택하면 선택 인스펙터 아래쪽에 Lane use 영역이 있습니다. 차로는 진행 방향 기준 왼쪽(lane 0)부터 오른쪽 순서로 나열되고, 차로마다 General / Bus only / Tram only / HOV only 중 하나를 고릅니다. 줄 앞의 색 막대와 지도에 칠해진 색이 같습니다(버스 빨강, 트램 황토색, HOV 청록). 선택한 링크는 테두리로만 강조하므로 선택 중에도 전용차로 색이 그대로 보입니다. 링크를 여러 개 선택하면 Leftmost / Rightmost / All lanes와 구분을 골라 Apply로 한꺼번에 지정합니다. 중앙버스전용차로 구간은 맨 왼쪽, 가로변 버스전용차로는 맨 오른쪽을 고르면 됩니다.

Selecting a link shows a Lane use area at the bottom of the selection inspector. Lanes are listed from left (lane 0) to right in the driving direction; pick General / Bus only / Tram only / HOV only for each. The colour bar in front of each row matches the colour on the map (bus red, tram ochre, HOV teal). Selected links are highlighted with an outline only, so dedicated-lane colours stay visible while selected. With several links selected, choose Leftmost / Rightmost / All lanes plus a lane use and press Apply — leftmost for a median bus lane, rightmost for a curbside one.

  • 값은 network.xml의 lane laneAccessType(BusOnly / TramOnly / HOVOnly)으로 저장되고, General은 속성을 쓰지 않습니다.
  • 엔진은 전용차로를 일반 차량 경로에서 뺍니다. 버스·트램은 PT Line 경로 표에서 PT lane을 켠 링크에서 전용차로로 달립니다.
  • HOV only: 엔진에는 아직 탑승 인원 모델이 없어서, 지금은 버스전용차로처럼 일반 승용차가 들어가지 않습니다.
  • 어떤 링크에서 다음 링크로 이어지는 커넥션이 모두 전용차로를 거치면 Validate가 경고합니다. 버스만 도는 회전이라면 그대로 두어도 되지만, 승용차 수요가 그 방향으로 가야 한다면 일반 차로 커넥션을 이어 주세요.
  • The value is saved as the lane's laneAccessType in network.xml (BusOnly / TramOnly / HOVOnly); General writes no attribute.
  • The engine keeps dedicated lanes out of general car routes. Buses and trams use them on links where the PT Line route table has PT lane turned on.
  • HOV only: the engine has no occupancy model yet, so for now general cars are kept out as on a bus lane.
  • Validate warns when every connection from one link to the next uses a dedicated lane. That is fine for a bus-only turn; if car demand needs that move, connect a general lane.

차로 구간 막기: 회전 포켓 · 버스베이Lane segments — turn pockets and bus bays

차로의 앞부분이나 뒷부분을 막으면 그 구간에서는 차가 그 차로를 쓸 수 없습니다. 교차로 앞에서만 생기는 좌회전 포켓 차로, 정류장 앞에만 있는 버스베이, 중간에 없어지는 차로를 이렇게 만듭니다. 링크 하나를 선택하면 선택 인스펙터의 Lane segments에 차로마다 줄이 있습니다. 왼쪽 상자에서 Open / Start blocked / End blocked를 고르고, 오른쪽 칸에 막을 길이(m)를 적습니다.

Blocking the first or last part of a lane keeps vehicles out of that lane there. Use it for a left-turn pocket that only exists before a junction, a bus bay in front of a stop, or a lane that ends part-way. With one link selected, the selection inspector lists every lane under Lane segments: pick Open / Start blocked / End blocked and type the blocked length in metres.

  • 회전 포켓: 교차로로 들어가는 링크의 맨 왼쪽 차로(우회전 포켓이면 맨 오른쪽)를 Start blocked로 두고, 링크 길이에서 포켓 길이를 뺀 값을 적습니다. 예를 들어 125 m 링크에 40 m 포켓이면 85를 적습니다. 처음 고르면 링크의 40%(10–60 m)가 열리도록 길이가 채워집니다.
  • 버스베이: 정류장이 있는 링크의 맨 오른쪽 차로를 막습니다. 정류장이 링크 끝 쪽이면 Start blocked, 링크 앞쪽이면 End blocked입니다. 정류장 위치(Station 워크스페이스)가 열린 구간 안에 있어야 합니다.
  • 한 차로는 시작이나 끝 한쪽만 막을 수 있습니다. 막는 길이는 5 m 이상이어야 하고, 차로를 바꿔 들어갈 수 있도록 10 m 이상은 열어 둬야 합니다. 링크의 한쪽 끝에서 모든 차로를 막을 수는 없습니다.
  • 막힌 부분은 지도에서 도로가 그만큼 좁아진 모습으로 그려집니다. 기존 네트워크(bucheon 등)의 포켓 차로와 같은 모양입니다.
  • 막힌 끝에 붙어 있던 커넥션은 그 끝에서 열려 있는 가장 가까운 차로로 옮겨집니다. 커넥션 ID가 그대로라 신호 현시도 유지됩니다. 옮긴 결과가 이미 있는 커넥션과 겹치면 지웁니다. 막혀 있던 끝을 다시 열면 커넥션이 자동으로 생기지 않으니 Connect 도구로 이어 주세요. 자동 커넥션 생성(Generate connections)과 Connect 도구도 막힌 끝에는 커넥션을 만들지 않습니다.
  • 저장하면 차로마다 <segment> 두 개(막힌 구간과 열린 구간, 링크 시작부터의 거리)가 쓰이고, lane의 shape는 열린 구간만 담도록 잘립니다. 곡선 링크도 형상을 따라 자릅니다. 셀(<cell>)은 바뀌지 않습니다.
  • 다른 편집을 해도 segment는 유지됩니다. 형상을 바꿔 링크 길이가 달라지면 막힌 길이는 그대로 두고 열린 구간이 늘거나 줄어듭니다 (10 m를 열어 둘 수 없으면 막힌 길이를 줄입니다). 차로 수를 바꾸면 차로 번호를 따라가므로 지워진 차로의 segment는 함께 사라집니다. Split은 막힌 구간을 실제 위치대로 두 링크에 나누고, Join은 첫 링크의 시작 쪽과 마지막 링크의 끝 쪽 막힘만 남깁니다. 링크 중간에 오게 되는 막힘은 지우고 알림으로 알려 줍니다.
  • Turn pocket — on the link entering the junction, set the leftmost lane (rightmost for a right-turn pocket) to Start blocked and enter the link length minus the pocket length: a 40 m pocket on a 125 m link blocks 85 m. The first time you pick it, the length is filled so that 40% of the link (10–60 m) stays open.
  • Bus bay — block the rightmost lane of the link with the stop: Start blocked when the stop is near the end of the link, End blocked when it is near the start. The stop position (Station workspace) must be inside the open part.
  • A lane can be blocked at its start or its end, not both. The blocked part must be at least 5 m long and at least 10 m must stay open so vehicles can change into the lane. At least one lane must stay open at each end of a link.
  • On the map the road simply gets narrower over the blocked part, the same way existing networks (bucheon and others) draw their pocket lanes.
  • Connections at the blocked end move to the nearest lane that is open there. They keep their IDs, so signal phases still find them; a moved connection that duplicates an existing one is deleted. Re-opening a blocked end does not add connections — draw them with the Connect tool. Generate connections and the Connect tool never connect a blocked end.
  • Saving writes two <segment> elements per lane (the blocked part and the open part, as distances from the link start) and cuts the lane shape to the open part, following the shape on curved links. <cell> elements are not changed.
  • Other edits keep the segments. When a shape edit changes the link length, the blocked length stays and the open part grows or shrinks (the blocked length is cut back if 10 m cannot stay open). Lane-count changes follow the lane number, so a removed lane takes its segment with it. Split divides a blocked part between the two links by position; Join keeps only a blocked start on the first link and a blocked end on the last one. A blocked part that would end up mid-link is removed, and the notification says so.

커넥션과 터미널 노드Connections and terminal nodes

노드를 선택하고 인스펙터의 Generate connections를 누르면 연결된 링크들의 기하 구조로부터 회전 방향(좌/직/우/유턴)을 추정해 커넥션을 자동 생성합니다. 링크를 선택한 상태에서 누르면 양 끝 노드에 함께 만듭니다. 노드나 링크를 옮기면 관련 커넥션은 자동으로 다시 계산됩니다.

회전 커넥션의 형상은 진입 차로 끝과 진출 차로 시작을 잇는 매끄러운 곡선(내부 점 8개)입니다. 곡선은 진입 차로의 끝 방향과 진출 차로의 시작 방향이 만드는 모서리 안쪽에 머물러, 두 차로의 연장선 밖으로 부풀거나 안쪽으로 급하게 꺾이지 않습니다. 거의 곧게 이어지는 직진 커넥션은 두 점 직선이고, 커넥션 길이(length)는 이 형상의 길이입니다. 이미 저장된 커넥션은 그대로 두며, 다시 생성하거나 양 끝 링크를 고칠 때 새 형상으로 바뀝니다. OSM 가져오기와 랜덤 네트워크도 같은 곡선을 씁니다.

예전 네트워크의 곡선만 새 형상으로 바꾸려면 Refit curves를 누르세요. Network tools 의 버튼은 선택한 노드(링크를 고르면 양 끝 노드)만, 아무것도 고르지 않으면 네트워크 전체를 다시 그립니다. 노드 인스펙터에도 같은 버튼이 있습니다. 커넥션 id·차로·회전·폭·속도는 그대로이고 shape와 length만 바뀌므로 신호 turn 이 깨지지 않습니다.

A turning connection is a smooth curve (eight interior points) from the end of the inbound lane to the start of the outbound lane. It stays inside the corner formed by the inbound lane's end direction and the outbound lane's start direction, so it never bulges past either lane's extension and does not kink sharply inward. A through connection that is nearly straight stays a two-point line, and the connection length is the length of this shape. Saved connections are left as they are until you regenerate them or edit a link at either end. OSM import and the random network use the same curve.

To bring an older network's curves up to date, press Refit curves. The Network tools button redraws the selected nodes (both end nodes of a selected link), or the whole network when nothing is selected; the node inspector has the same button. Connection ids, lanes, turns, width and speed are kept and only shape and length change, so signal turns stay valid.

차로 짝짓기도 OSM 가져오기와 같은 규칙입니다. 좌회전은 맨 왼쪽 차로끼리, 우회전은 맨 오른쪽 차로끼리 잇고, 직진은 오른쪽을 맞춰 차로를 짝짓습니다 (진출 링크의 차로가 더 많으면 남는 왼쪽 차로는 맨 왼쪽 진입 차로가 함께 잇습니다). 끝이 막힌 차로(segment)는 빼고 셉니다. 커넥션 id 는 진입 링크 → 좌·직·우 → 차로 순서로 매깁니다.

Lanes are paired by the same rule as OSM import: a left turn joins the leftmost lanes, a right turn the rightmost lanes, and through traffic pairs lanes aligned to the right (when the outbound link has more lanes, the leftmost inbound lane also feeds the extra left lanes). Lanes whose end is blocked by a segment are left out. Connection ids follow inbound link → left/through/right → lane.

신호 교차로에서 커넥션을 다시 만들면 id 가 바뀌어 signal.xml 의 turn 이 엉뚱한 커넥션을 가리키거나, 어느 turn 에도 없는 커넥션이 생깁니다. 그러면 시뮬레이션이 시작하자마자 멈춥니다. 다시 만들면 경고가 뜨고, 저장할 때 문제 노드를 알려 주므로 Signal 탭에서 새 커넥션을 turn 에 넣어 주세요.
Regenerating connections at a signalised intersection changes their ids, so signal.xml turns may point at the wrong connections or leave some connections in no turn, which stops the simulation at start. A warning appears when you regenerate, and saving lists the affected nodes — assign the new connections to turns in the Signal tab.

Select a node and press Generate connections in the inspector to infer turn directions (left/through/right/U-turn) from the attached links' geometry and create the connections; with a link selected it does both end nodes. Moving a node or link recomputes the affected connections automatically.

어느 노드에도 연결되지 않은 링크 끝점에는 저장할 때 자동으로 터미널(terminal) 노드가 만들어져 연결됩니다. 터미널 노드는 차량이 네트워크에 들어오고 나가는 지점으로, OD Matrix의 기·종점이 됩니다. 터미널의 역할은 포트 방향으로 정해집니다. out 포트면 출발지(source), in 포트면 도착지(sink)입니다.

Link endpoints not attached to any node get a terminal node created automatically on save. Terminal nodes are where vehicles enter and leave the network and serve as the origins and destinations in the OD Matrix. The port direction decides the role: an out port makes it a source, an in port a sink.

검증Validation

Validate 버튼은 누락된 참조, 잘못된 기하 구조 등을 검사합니다. 결과 요약은 도구 패널의 배지에 남고(검사 전에는 Not validated), 배지를 클릭하면 목록이 열립니다. 목록 항목에 마우스를 올리면 전체 내용이 보이고, 클릭하면 목록이 닫히면서 지도가 그 객체로 이동·확대되고 객체가 선택됩니다. 이때 지도 아래쪽에 이슈 줄이 떠서 목록을 다시 열지 않고도 ‹ / › 버튼이나 F8 / Shift+F8로 다음·이전 이슈로 넘어갈 수 있습니다. 중간에 네트워크를 고치면 다음 이동 때 다시 검사한 뒤 이어서 보여 줍니다. 자동으로 수정할 수 있는 문제는 목록 위의 Clean up으로 한 번에 고칩니다. 지도 위의 검증 마커는 배지 옆의 × 또는 Esc로 숨길 수 있습니다.

The Validate button checks for missing references, bad geometry, and so on. The summary stays in a badge on the tools panel (Not validated before you run it); click it to open the list. Hover an entry to see its full text; clicking it closes the list, moves and zooms the map to that object and selects it. An issue bar then appears at the bottom of the map, so you can step to the next or previous issue with ‹ / › or F8 / Shift+F8 without reopening the list. If you edit the network in between, the next step re-validates and carries on. Auto-fixable problems are repaired in one go with Clean up at the top of the list. Network 상충 · 통행우선권 편집기Conflict / Right-of-Way editor

도구 레일의 Conflict(W)를 켜고 교차로 노드를 클릭하면 전용 패널이 열립니다. 편집 중에는 해당 교차로 이외의 지도 영역이 흐려지므로 대상에 집중할 수 있습니다. 결과는 network.xml의 노드 안에 <conflict> 요소로 저장되며, 엔진은 이 요소를 무시하므로 기존 시뮬레이션에 영향을 주지 않습니다.

Enable Conflict (W) on the tool rail and click an intersection node to open its panel. While editing, the rest of the map dims so you can focus on that junction. Results are stored as <conflict> elements inside the node in network.xml; the engine ignores them, so existing simulations are unaffected.

  • 이동류(movement): (진입 링크 → 진출 링크) 조합이 같은 커넥션들의 묶음입니다. 별도의 데이터가 아니라 기존 커넥션에서 파생되며, 신호의 turn과 1:1로 대응합니다. 회전 종류(직진/좌/우/유턴)는 기하 구조에 따라 자동으로 분류되며, 필요하면 직접 바꿀 수 있습니다.
  • Detect: 이동류 사이의 상충을 자동으로 판정합니다: Crossing(교차, 동시에 녹색을 줄 수 없음), Merging(합류, 양보), Diverging(분기, 신호 상충이 아님).
  • Auto: 도로 등급과 회전 종류에 따라 통행우선권(우선순위, 정지/양보 의무)을 일괄 부여합니다.
  • Validate: 우선순위의 모순(순환 등)을 검사합니다.
  • Movements — the group of connections sharing one (from-link → to-link) pair. They are derived from the existing connections rather than stored separately, and correspond one-to-one with a signal turn. The turn kind (through/left/right/U) is classified from geometry and can be overridden.
  • Detect — classifies conflicts between movements: Crossing (cannot be green together), Merging (yield), and Diverging (not a signal conflict).
  • Auto — assigns right-of-way (priority, stop/yield obligations) from road class and turn kind.
  • Validate — checks for contradictory priorities such as cycles.
Tip. 상충 판정 결과는 Signal 워크스페이스의 Auto phases에서 그대로 사용됩니다. 교차 상충이 없는 이동류들이 한 현시로 묶입니다.
Tip. The Signal workspace's Auto phases reuses these conflicts directly — movements without a crossing conflict are grouped into one phase.

Workspace OD Matrix

담당 파일:File: odmatrix.xml

시간대별 통행 수요를 편집합니다. 수요는 기점(origin) 터미널 노드 → 종점(destination) 터미널 노드 쌍과 교통량(flow, 대/시)으로 정의되며, 차종별 매트릭스로 나뉘어 저장됩니다.

Edits travel demand per time slice. Demand is a pair of origin terminal node → destination terminal node with a flow (veh/h), stored in per-vehicle-type matrices.

차종Vehicle types

엔진이 OD로 표현할 수 있는 차종은 nv(일반차), av(자율차), tr(화물차), cav(연결 자율차) 넷이며, 차종마다 odmatrix.xml 안에 별도의 매트릭스가 있습니다. Vehicle type 드롭다운은 그중 이 프로젝트의 parameter_xml/vehicletypes.xml에 실제로 정의된 차종만 보여 줍니다. 정의되지 않은 차종으로 수요를 만들면 엔진이 차종을 조회하지 못하기 때문입니다.

The engine can express four vehicle types in an OD matrix — nv (normal), av (autonomous), tr (truck), cav (connected autonomous) — each its own matrix inside odmatrix.xml. The Vehicle type dropdown lists only those actually defined in this project's parameter_xml/vehicletypes.xml, because demand for an undefined type would make the engine fail its type lookup.

  • New — opens the new-matrix dialog (empty or randomly generated).
  • Duplicate — copies the current matrix as the next time slice; handy for peak and off-peak profiles.
  • Delete — removes the current matrix (Ctrl+Z restores it before you save).
  • Start time / Duration (min) — the slice each matrix applies to.

The scenario decides which matrix runs. By default the odMatrixID in the Scenario workspace applies to the whole scenario; to use different matrices at different times, split the scenario card's Demand schedule into segments. Pick the new matrix's ID in one of them to simulate what you just built.

Allowed Sources: 수요 진입점 제한Allowed Sources — restricting where demand enters

네트워크의 터미널 source를 모두 쓰지 않고 일부 진입점에서만 수요가 들어오게 하려는 경우에 사용합니다. 이 설정은 랜덤 생성 전용 옵션이 아니라 해당 odmatrix.xml 전체에 적용되는 제약이며 파일에 함께 저장됩니다.

Use this when demand should enter through only some of the network's terminal sources. It is not a one-off generation option — it is a constraint on the whole odmatrix.xml and is saved with the file.

  1. OD tools의 Select source links를 누릅니다. 사이드바가 접히고 화면 아래에 선택 모드 바가 나타납니다.
  2. 지도에서 터미널 source에서 나오는 링크를 클릭할 때마다 그 source가 추가되거나 해제됩니다. Source가 없는 링크는 무시되며, 아래 바에 그 이유가 표시됩니다. (선택된 source의 링크는 지도에 강조 표시됩니다.)
  3. Esc를 누르거나 Done을 눌러 선택을 마칩니다. 선택하는 동안에는 같은 버튼이 Done picking으로 바뀝니다.
  1. Press Select source links in the OD tools panel — the sidebar collapses and a pick-mode bar appears at the bottom.
  2. Each click on a link leaving a terminal source toggles that source. Links with no source attached are skipped, with the reason shown in the bar. Links of selected sources are highlighted on the map.
  3. Finish with Esc or Done — the same button reads Done picking while picking.

선택을 마치면 사이드바에 Allowed Sources 줄이 개수 배지와 함께 나타납니다. source가 여러 개면 목록은 접혀 있고, 줄을 누르면 펼쳐집니다(칩을 클릭하면 지도가 그 위치로 이동하고, ×를 누르면 해제됩니다). 이때 다음 규칙이 적용됩니다:

Once sources are chosen, the sidebar shows an Allowed Sources row with a count badge. With more than a few sources the list starts collapsed; click the row to expand it (click a chip to focus it on the map, × to remove it). The following applies:

  • 허용 목록 밖에 있는 origin의 행은 흐리게 표시되고 flow 입력이 잠깁니다.
  • 랜덤 생성, 수요 스케일링, 지도를 클릭해 행을 추가하는 기능은 모두 허용된 source만 대상으로 합니다.
  • 허용되지 않은 source에 flow가 남아 있으면 저장이 거부됩니다.
  • Rows whose origin is outside the list are dimmed and their flow becomes read-only.
  • Random generation, demand scaling, and map-click row creation all restrict themselves to allowed sources.
  • Saving is refused while any non-allowed source still carries flow.
기존 수요는 자동으로 지워지지 않습니다. 이미 수요가 들어 있는 파일에 제약을 새로 설정하면, 제약 밖 source의 기존 flow가 그대로 남아 있어 저장할 수 없습니다. 선택을 마칠 때 "0으로 만들까요?" 확인창이 뜨며, 거절했더라도 Allowed Sources 바의 경고줄에 있는 Set to 0 버튼으로 언제든 한 번에 0으로 정리할 수 있습니다 (Ctrl+Z로 되돌릴 수 있습니다).
Existing demand is not cleared for you. Applying the constraint to a file that already has demand leaves flows from now-disallowed sources in place, and saving stays blocked. You are offered a "set them to 0?" confirmation when you finish picking; if you decline, the Set to 0 button in the Allowed Sources warning row does it at any time (undoable with Ctrl+Z).

저장 전 검사Checks before saving

편집하는 동안 문제가 생기면 패널 위쪽에 한 줄로 표시되고, 고치기 전에는 저장되지 않습니다. 메시지는 표의 순번이 아니라 매트릭스 ID(Matrix #1)로 가리킵니다. 같은 차종 표 안에 같은 source→sink 쌍이 두 번 있으면 엔진이 수요를 두 번 만들기 때문에 오류로 봅니다. 시작 시각이 같거나 시간대가 겹치는 매트릭스는 경고만 보여 주고 저장은 그대로 됩니다. 시뮬레이션은 시나리오의 odMatrixID가 가리키는 매트릭스 하나만 쓰므로, 서로 대안인 매트릭스라면 겹쳐도 괜찮습니다.

Problems found while you edit show as one line at the top of the panel, and saving waits until they are fixed. Messages name matrices by ID (Matrix #1), not by position. The same source→sink pair twice in one vehicle table is an error, because the engine would create that demand twice. Matrices with the same or overlapping start times only get a warning and still save: a run uses the single matrix named by the scenario's odMatrixID, so alternative matrices may overlap.

Workspace Mode

담당 파일:File: mode.xml

NextSIM은 하나의 네트워크 안에서 링크별로 미시(micro) / 중시(meso) 시뮬레이션을 섞어 실행할 수 있는 하이브리드 시뮬레이터입니다. Mode 워크스페이스에서는 기간(period)별로 어떤 링크를 어느 방식으로 시뮬레이션할지 지정합니다.

NextSIM is a hybrid simulator: within one network, each link can run in micro or meso mode. The Mode workspace assigns which links run which way, per period.

  1. 기간을 선택하거나 추가하고 적용 시간 범위를 정합니다.
  2. 지도에서 링크를 클릭할 때마다 micro ↔ meso가 토글됩니다. micro 링크는 하늘색, meso 링크는 주황색으로 표시됩니다.
  3. 도구 패널의 All micro / All meso 버튼으로 현재 기간의 모든 링크를 한 번에 지정할 수 있습니다.
  4. 일부 구역만 한꺼번에 바꾸려면 링크를 여러 개 고릅니다. 도구 패널의 Box select를 켜고 지도에서 끌면 상자 안에 중심이 들어온 링크가 선택되고(보라색 테두리), Shift를 누른 채 끌면 토글 없이도 선택에 더해집니다. 표의 필터(모드·Lanes·id)로 걸러 낸 뒤 Select listed를 눌러 고를 수도 있습니다. 그다음 Set micro / Set meso를 누르면 한 번에 바뀌고, Ctrl+Z 한 번으로 되돌릴 수 있습니다. Clear나 Esc로 선택을 해제합니다.
  5. 패널의 표에서 기간별 지정 현황을 확인하고 저장합니다.
  1. Select or add a period and set its time range.
  2. Each click on a link toggles it between micro and meso. Micro links are light blue, meso links orange.
  3. All micro / All meso in the tools panel sets every link in the current period at once.
  4. To change one area at once, select several links. Turn on Box select in the tools panel and drag on the map: links whose centre falls inside the box are selected (purple outline). Shift+drag adds to the selection without the toggle. You can also narrow the table with its filters (mode, Lanes, id) and press Select listed. Then Set micro / Set meso changes them all in one step, undone by a single Ctrl+Z. Clear or Esc drops the selection.
  5. Review the assignment table in the panel and save.
Tip. 관심 구간(예: 분석 대상 교차로 일대)만 micro로 두고 외곽은 meso로 두면 정확도와 계산 속도를 함께 확보할 수 있습니다. 검지기는 micro 링크에서만 기록되므로 Infrastructure 워크스페이스와 함께 확인하세요.
Tip. Keeping the area of interest (say, the junctions you are studying) in micro and the rest in meso buys accuracy and speed together. Detectors only record on micro links, so check this alongside the Infrastructure workspace.

수요 스케줄Demand schedule

한 시나리오 안에서도 시간대마다 다른 수요를 쓸 수 있습니다. 예를 들어 09:00–12:00 시나리오라면 09:00–10:00에는 OD 매트릭스 1을, 10:00–12:00에는 매트릭스 3을 쓰도록 나눌 수 있습니다. 카드 타임라인의 Vehicles(차량)와 Passengers(승객) 두 줄에서 따로 정합니다. 차량 OD는 언제나 이 스케줄로 정하며, 따로 고르는 OD Matrix ID 칸은 없습니다. 차량 쪽은 odmatrix.xml의 매트릭스를, 승객 쪽은 passenger.xml의 승객 OD 매트릭스(od_pax id)를 고릅니다.

A scenario can use different demand at different times. In a 09:00–12:00 scenario, for example, you can run OD matrix 1 from 09:00 to 10:00 and matrix 3 from 10:00 to 12:00. The card timeline's Vehicles and Passengers rows are set independently. Vehicle OD is always chosen through this schedule; there is no separate OD Matrix ID field: the vehicle row picks matrices from odmatrix.xml, the passenger row picks passenger OD matrices (od_pax ids) from passenger.xml.

  • 각 줄의 막대는 시나리오 시작부터 끝까지를 나타내고, 구간 블록에는 OD 1 · 09:00–10:00처럼 매트릭스와 시간이 적혀 있습니다. 신호 편집기의 페이즈 막대와 같은 방식입니다.
  • 줄 이름 옆 +: 줄이 비어 있으면 시나리오 전체를 덮는 구간을 하나 만들고, 이미 구간이 있으면 선택한 구간(없으면 마지막 구간)을 가운데에서 둘로 나눕니다. 나뉜 지점은 5분 단위로 맞춰집니다.
  • 블록을 누르면 타임라인 아래에 상세 줄이 열립니다. 매트릭스를 고르고, 시작·끝 시각을 입력하거나 −15/−5/+5/+15분 버튼으로 옮기고, 휴지통으로 구간을 지웁니다. 블록 양 끝을 마우스로 끌어도 되며 5분 단위로 붙습니다. 차량 구간은 최소 하나여야 하므로 마지막 차량 구간은 지울 수 없습니다(매트릭스를 바꾸세요).
  • 붙어 있는 두 구간의 경계를 옮기면 이웃 구간도 함께 늘거나 줄어듭니다. 구간은 시나리오 시간 밖으로 나가거나 서로 겹칠 수 없습니다.
  • 구간 사이가 비어 있으면(빗금) 그 시간에는 그 종류의 수요를 만들지 않습니다.
  • Each row's bar spans the scenario from start to end; segment blocks are labelled with their matrix and time, such as OD 1 · 09:00–10:00 — the same idea as the signal editor's phase bar.
  • + next to the row name: on an empty row it creates one segment covering the whole scenario; otherwise it splits the selected segment (or the last one) in half, with the cut rounded to 5 minutes.
  • Click a block to open its detail line under the timeline: pick the matrix, type the start and end, nudge them with the −15/−5/+5/+15 min buttons, or delete the segment. You can also drag either end of a block; it snaps to 5 minutes. A scenario needs at least one vehicle segment, so the last one cannot be deleted (change its matrix instead).
  • Moving a boundary that two segments share moves both. Segments cannot leave the scenario window or overlap.
  • A gap between segments (hatched) means no demand of that kind during that time.

차량 스케줄이 없는 예전 파일은 odMatrixID의 매트릭스로 시나리오 전체를 덮는 구간 하나로 보여 주고, 저장하면 그 구간이 파일에 그대로 적힙니다. 새 시나리오 창의 Vehicle OD matrix도 그런 첫 구간이 됩니다(기본값은 odmatrix.xml의 첫 매트릭스). odMatrixID는 늘 첫 차량 구간의 매트릭스로 맞춰 저장됩니다(엔진과 다른 도구가 읽습니다). 승객 스케줄은 선택이며, 비어 있으면 승객 매트릭스 0을 시나리오 전체에 씁니다 (줄에 Whole window: passenger matrix 0로 표시). 시나리오의 시작 시각이나 길이를 바꾸면 구간도 새 시간에 맞춰 잘립니다. 스케줄이 기존 시간을 빈틈없이 채우고 있었다면 처음과 끝이 새 시작·끝에 맞춰 늘어납니다. Run 패널에서 시작·종료 시각을 바꿔 실행할 때도 같은 규칙이 적용되고, Run 패널의 시나리오 정보에는 Vehicle demand와 Passenger demand가 한 줄씩 요약됩니다.

An older file without a vehicle schedule is shown as one segment covering the whole scenario with its odMatrixID matrix, and saving writes that segment to the file. The Vehicle OD matrix in the New Scenario dialog becomes such a first segment too (default: the first matrix in odmatrix.xml). odMatrixID is always saved as the first vehicle segment's matrix, because the engine and other tools read it. The passenger schedule is optional; when it is empty, passenger matrix 0 runs for the whole scenario (the row says Whole window: passenger matrix 0). Changing the scenario's start time or duration clips the segments to the new window; a schedule that filled the old window without gaps is stretched so it starts and ends with the new window. The same rule applies when you change the start and end times in the Run panel before a run, and the Run panel's scenario info sums up Vehicle demand and Passenger demand on one line each.

카드의 토글 스위치로 신호제어·V2X·DTA를 켜고 끄면 관련 입력란이 함께 활성화/비활성화됩니다. 편집기 하단의 24시간 타임라인에는 각 시나리오가 하루 중 어느 구간을 차지하는지 색 막대로 표시되며, 막대를 클릭하면 해당 카드로 스크롤됩니다. 시간이 겹치는 시나리오는 별도 줄로 나뉘어 표시됩니다.

The card's toggles for signal control, V2X, and DTA enable and disable the related fields with them. The 24-hour timeline at the bottom shows which part of the day each scenario covers as a coloured bar; clicking a bar scrolls to its card. Overlapping scenarios are drawn on separate rows.

파일에 없는 id를 가리키던 기존 값은 지우지 않고 “99 (missing)”처럼 빨갛게 남겨 둡니다. 수요 스케줄 구간이 없는 매트릭스를 가리키거나(엔진이 그 시간에 수요를 하나도 만들지 않음) 시나리오 시간 밖으로 나가거나 겹치면, 몇 번째 구간인지 패널 머리에 알려 주고 저장을 막습니다. 차량 구간이 하나도 없어도 저장이 막힙니다. TOD id는 현재 엔진이 시나리오별로 고르는 데 쓰지 않아 주황색 경고만 띄우고 저장은 막지 않습니다.

An existing value that points at an id the file does not have is kept and shown in red as “99 (missing)”. A demand segment that points at a missing matrix (the engine would generate no demand then), leaves the scenario window or overlaps another blocks saving, and the panel header names the segment. A scenario without any vehicle segment cannot be saved either. The engine does not currently use the TOD id to pick a schedule, so a missing TOD id only raises an orange warning and does not block saving.

Workspace Signal

담당 파일:Files: signal.xml signalTOD.xml

교차로 신호를 편집합니다. Signal 탭에서는 신호가 있는 교차로마다 지도에 주황 점선 링이, 지금 편집 중인 교차로에는 파란 링이 그려집니다. 대상 교차로는 세 가지 방법으로 고릅니다.

Edits intersection signals. While the Signal tab is open, every junction that has a signal gets a dashed orange ring on the map, and the one you are editing gets a blue ring. Pick the target junction in one of three ways:

  • 지도 클릭: 교차로의 노드나 커넥션 어디를 눌러도 그 교차로가 선택됩니다. 단, 지금 편집 중인 교차로의 커넥션은 Turn 편집(아래)에 쓰입니다.
  • 노드 목록: 패널의 목록에 10001135 · 3 plans · 12 turns처럼 플랜·Turn 수가 함께 나옵니다. 고르면 지도가 그 교차로로 이동하고, 패널에 가리지 않게 왼쪽 지도 영역 가운데에 맞춰집니다.
  • 검색: 목록 옆 입력란에 id 일부를 치면 목록이 걸러지고, Enter를 누르면 그 노드로 이동합니다. 신호가 없는 노드도 id 전체를 입력하면 찾아갑니다.
  • Click the map — a click anywhere on a junction, node or connection, selects it. Connections of the junction you are already editing are used for turn editing (below).
  • Node list — the panel list shows each node with its counts, for example 10001135 · 3 plans · 12 turns. Picking one moves the map to it, centred in the part of the map the panel does not cover.
  • Search — type part of an id in the box next to the list to filter it; Enter jumps to the node. Typing a full id also finds nodes that have no signal yet.

신호가 없는 교차로를 고르면 패널에 “Node X has no signal.”이 뜹니다. 이때는 아무것도 만들어지지 않고, Add signal(빈 신호)이나 Auto phases…(자동 생성)를 눌러야 신호가 생깁니다. 지도에서 노드를 눌러 보기만 해서는 저장할 변경이 생기지 않습니다.

Selecting a junction without a signal shows “Node X has no signal.” Nothing is created until you press Add signal (an empty signal) or Auto phases… (generated). Just clicking around the map never leaves changes to save.

신호는 아래 세 단계로 구성합니다. 각 단계의 추가 버튼(+ Turn, + Phase, + Clearance, + Time block)은 해당 표 위에 있고, 도구 줄에는 Reload와 Auto phases만 있습니다. 저장은 상단 바의 Save로 합니다.

A signal is built in three layers. Each layer's add button (+ Turn, + Phase, + Clearance, + Time block) sits above its table; the tools strip keeps only Reload and Auto phases. Save with Save in the top bar.

  1. Turn: 함께 신호를 받는 커넥션 묶음(이동류)입니다. Turn을 선택하면 지도에서 해당 교차로의 커넥션들이 강조되고, 커넥션을 클릭해 이 Turn에 넣거나 뺄 수 있습니다(선택된 커넥션은 초록색으로 표시됩니다). 회전 종류(L/S/R)와 RTOR(적신호 우회전) 같은 타입을 지정합니다.
  2. Plan → Phase: Plan에는 주기(cycle)와 옵셋(offset)이 있고, 그 안의 Phase들이 순서대로 진행됩니다. 각 Phase에 지속시간과 녹색을 받는 Turn 목록을 지정합니다. + Clearance 버튼은 3초짜리 전이(clearance) 현시를 추가합니다 우회전(RTOR)은 이 현시에서도 녹색으로 유지됩니다. Phase 타임라인 그래프에서 현시 구성을 한눈에 확인할 수 있고, 타임라인이나 표에서 현시를 클릭하면 그 현시에 녹색인 커넥션이 지도에 표시됩니다.
  3. TOD: 하루를 구간(time block)으로 나눠 시간대별로 어떤 Plan을 쓸지 배정합니다 (예: 첨두 Plan / 비첨두 Plan). + Time block은 아직 비어 있는 첫 시간대에 구간을 하나 추가합니다.

Duplicate plan은 지금 플랜을 복사해 새 플랜을 만듭니다. 플랜이 하나도 없을 때만 이 버튼이 + New plan(120초짜리 현시 하나)으로 바뀝니다. 새 플랜은 TOD에 배정해야 실제로 쓰입니다.

편집 중 저장을 막는 문제가 생기면(예: 현시 합이 주기와 다름 phases 205/200s) 패널 머리에 빨간 줄로 바로 표시됩니다. 다른 교차로의 문제라면 그 줄을 눌러 해당 교차로로 이동할 수 있습니다.

  1. Turn — a group of connections that get the same signal. Selecting a turn highlights that junction's connections on the map, and clicking a connection adds or removes it from the turn (members show green). Set its turn kind (L/S/R) and type, such as RTOR (right turn on red).
  2. Plan → Phase — a plan carries a cycle and offset, and its phases run in order. Give each phase a duration and the list of turns that go green. + Clearance adds a 3-second clearance phase — right turns (RTOR) stay green through it. The phase timeline graph shows the whole cycle at a glance, and clicking a phase in the timeline or the table paints its green connections on the map.
  3. TOD — divides the day into time blocks and assigns a plan to each (peak plan, off-peak plan, and so on). + Time block adds a block in the first part of the day that is not covered yet.

Duplicate plan copies the current plan into a new one. Only when the node has no plan at all does the button read + New plan (one 120-second phase). A new plan is used only once the TOD schedule assigns it.

A problem that would block saving, such as phase durations that do not add up to the cycle (phases 205/200s), shows at once as a red line in the panel header. If it belongs to another junction, click the line to go there.

Apply plan to…: 다른 교차로에 플랜 복사Apply plan to… — copying a plan to other junctions

Apply plan to…를 누르면 다른 신호 교차로의 체크 목록이 열립니다. 고른 교차로에 지금 플랜이 같은 plan id로 복사됩니다(이미 있으면 교체, 없으면 추가). Copy TOD schedule too를 켜면 TOD도 함께 복사하는데, 그 TOD가 쓰는 플랜이 대상 교차로에 모두 있을 때만 복사합니다. 한 번의 적용은 Ctrl+Z 한 번으로 되돌릴 수 있습니다.

Apply plan to… opens a checklist of the other signal junctions. The current plan is copied to each chosen junction under the same plan id (replacing it if it exists, otherwise added). With Copy TOD schedule too the TOD schedule is copied as well, but only where every plan it uses exists on the target. One apply is undone with a single Ctrl+Z.

현시는 Turn id로 정의되고 Turn은 교차로마다 다른 커넥션 묶음이라, 아무 교차로에나 복사하면 엉뚱한 이동류가 함께 녹색이 될 수 있습니다. 그래서 다음 조건을 모두 만족하는 교차로만 고를 수 있고, 나머지는 이유와 함께 흐리게 표시됩니다.

Phases name turns by id, and a turn is a different set of connections at every junction, so copying blindly could turn conflicting movements green together. Only junctions that meet all of these can be ticked; the rest are greyed out with the reason:

  • 진입 링크 수가 같습니다.
  • Turn id가 같고, 각 Turn의 회전(L/S/R)과 타입이 같습니다.
  • 진입 링크를 각도 순으로 늘어놓았을 때 모든 Turn의 진입 위치가 같은 회전으로 맞아떨어집니다. 즉 마주 보는/옆에 있는 이동류 관계가 그대로입니다.
  • The same number of approach links.
  • The same turn ids, each with the same movement (L/S/R) and type.
  • With the approaches ordered by angle, one rotation lines up every turn's approach — opposing and adjacent movements stay opposing and adjacent.

offset도 그대로 복사되므로, 연동이 필요하면 복사 뒤 교차로별로 고쳐 주세요.

The offset is copied as is; adjust it per junction afterwards if they need coordinating.

생성 규칙은 다음과 같습니다:

The generation rules are:

  • 녹색현시는 교차 상충이 없는 이동류들의 묶음입니다. 좌회전은 대향 직진과 교차하므로 자동으로 분리되어 보호좌회전이 됩니다.
  • 우회전은 신호 대상에서 빠져 RTOR 타입으로 모든 현시에 녹색으로 포함됩니다.
  • 녹색현시마다 뒤에 황색현시가 하나씩 삽입됩니다. 예를 들어 4현시라면 signal.xml에 기록되는 현시는 8개가 됩니다.
  • 현시 시간은 임계 차로 수에 비례해 배분되고, 최소녹색시간으로 보정됩니다.
  • A green phase is a group of movements with no crossing conflict. Left turns cross the opposing through movement, so they separate out on their own — protected left turns.
  • Right turns are excluded from the signal and emitted as RTOR turns that stay green in every phase.
  • Each green phase is followed by one yellow phase, so a 4-phase plan becomes 8 phases in signal.xml.
  • Durations are split in proportion to critical lane count, then corrected against the minimum green time.
Tip. Network 워크스페이스의 New junction… 템플릿으로 교차로를 만들면 기본 신호가 함께 생성됩니다. 외부에서 가져온 네트워크에는 Auto phases의 "신호가 없는 모든 교차로" 대상을 쓰면 편리합니다.

Road: 버스 정류장Road — bus stops

  1. 도구 패널의 Add station을 누른 뒤 지도에서 정류장을 놓을 링크를 클릭합니다. 클릭 지점에서 가장 가까운 차로에 스냅되어 정차면이 생성됩니다.

  2. Clicking a stop opens the right panel to edit its attributes: linkRef/laneRef (which link and lane), pos (position along the link), and parkingLots (simultaneous berths, minimum 1). Changing the lot count updates the map immediately.

Under each row, Name (display only; the engine ignores it) and a line summary (N lines) share one line; click the summary to list the lines. Pos is shown to two decimals while the stored value stays as it is until you edit it. Deleting a stop needs no confirmation; Ctrl+Z brings it back.

Rail: 철도역과 출구Rail — stations and exits

  • Add rail station: 지도에서 클릭한 위치에 철도역을 만듭니다. 역은 도로와 독립적으로 배치되며, 이름과 운영 모드(지하철 등)를 지정합니다.
  • Add exit: 역을 선택한 상태에서 도로 링크를 클릭하면 그 링크의 진행방향 오른쪽 보도 위치에 출구가 생성됩니다. 출구는 역과 도로망(보행 접근)을 잇는 지점이며, offset(링크 위의 위치)과 accessTime(역까지 걷는 시간) 속성이 있습니다.
  • Add rail station — places a station at the clicked point. Stations sit independently of the road network; give each a name and operating mode (subway and so on).
  • Add exit — with a station selected, clicking a road link creates an exit on the right-hand pavement in that link's direction. An exit joins the station to the road network for walking access and carries an offset (position along the link) and accessTime (walk time to the station).

지도에서 철도역은 전동차 그림이 들어간 둥근 사각형 배지로 보입니다. 한 노선만 서는 역은 그 노선 색으로, 색이 다른 노선이 둘 이상 서는 환승역은 짙은 배지 아래에 노선 색 점을 나란히 붙여 표시합니다. 출구는 출구 번호가 적힌 원으로, 역과 점선으로 이어집니다. 번호는 출구 id 에서 정합니다. id 에 _ - : . / 가 있으면 마지막 조각을 쓰고 (1001_3 → 3), 세 글자 이하면 그대로 씁니다. 역 id 에 번호를 이어 붙인 전역 id 라면 (역 31000006, 출구 31000007) 그 차이를 쓰고, 어느 것도 아니면 역 안에서의 순번을 씁니다. Exits 표 왼쪽의 동그라미가 지도에 찍히는 번호입니다. 배지와 번호는 확대·축소해도 거의 같은 크기로 보이고, 멀리서 보면 역과 겹치는 출구는 숨겨집니다.

On the map a rail station is a rounded badge with a train glyph. A station served by a single line takes that line's color; an interchange (two or more line colors) gets a dark badge with a row of colored dots underneath. Exits are circles showing the exit number, linked to the station by a dotted line. The number comes from the exit id: if the id contains _ - : . / the last part is used (1001_3 → 3); an id of three characters or fewer is used as is; a global id that continues the station id (station 31000006, exit 31000007) shows the difference; otherwise the exit's position in the station is used. The circle at the left of each row in the Exits table is the number shown on the map. Badges and numbers keep roughly the same size as you zoom, and exits that would overlap their station are hidden when zoomed out.

  2. Then click links in service order on the map to build the link sequence. Only links that continue from the previous one (directly or through a node) can be picked, and a link cannot be added twice. Link IDs are picked on the map, not typed in the table.
  3. With a route row selected, map clicks go right after that row; with no selection they append to the end. Click the selected row again to deselect it. The selected row's link is highlighted separately (yellow) on the map.
  4. Clicking a stop on the map assigns it to the selected row when that row is the stop's link (click again to clear it), or to the row that already holds that link. If the link is not in the route yet, it is added (when it connects) together with the stop.
  5. Use the ↑ / ↓ buttons on each row to reorder (seq is renumbered). Rows that do not connect to the previous link get a ⚠ mark, and the line will not save while any remain. Removing a row needs no confirmation; Ctrl+Z undoes it.
  6. The line under the route table shows progress (10 links · 3 stops · last added …), where the next map click will go, and any warning. Adding a link no longer pops up a toast.
  7. For each row you can set PT lane (whether it runs in the bus lane) and the stop it serves. A disabled stop box means there is no station on that link — add one in the Station tab first. The selected line is highlighted in colour on the map.
  8. To delete a line, press the trash button next to the Line selector. Stations stay; the line is only removed from their line lists. Ctrl+Z undoes it before you save. The + button next to it is the same as Add PT line.

Rail: 철도 노선Rail — rail lines

철도 노선은 링크가 아니라 역 순서(stationSeq)로 정의합니다. 노선을 선택한 뒤 지도에서 철도역을 클릭하면 순서에 추가되고, 표에서는 역의 순서를 옮기거나 삭제하고 역별 timeOffset(기점에서 출발한 뒤 그 역에 도달하기까지 걸리는 시간)을 편집할 수 있습니다. 노선의 역 연결은 지도에 노선 색 선으로 그려집니다.

A rail line is defined by a station sequence rather than links. With a line selected, clicking a rail station appends it; the table lets you reorder, remove, and set each station's timeOffset (time from the first departure). The line's station chain is drawn on the map in the line color.

  • Line color: 지도에 그릴 노선 색을 고릅니다. railPTline.xml 의 <Line color="#rrggbb"> 로 저장되며 화면 표시에만 쓰이고 엔진은 읽지 않습니다. 색을 정하지 않으면 기본색을 씁니다. 방향 접미사(_up, _down, 상행·하행 등)를 뗀 노선 번호가 1~9 이면 수도권 지하철 그 호선 색, 아니면 팔레트 색이라 1_up 과 1_down 은 같은 색이 됩니다. Reset 은 기본색으로 되돌리고, Apply to … 는 같은 계통의 반대 방향 노선에도 같은 색을 줍니다.
  • Departure times: 맨 위에 출발 횟수, 첫차·막차, 평균(최소·최대) 배차 간격이 나오고, 그 아래 24시간 띠에 출발 시각이 눈금으로 찍힙니다. 띠는 03시에 시작해 다음 날 03시에 끝납니다.
  • Generate from headways: 구간마다 첫차·막차·배차 간격(분)을 넣고 Replace (목록 교체) 또는 Merge(기존 목록에 합치기)를 누르면 시각이 만들어집니다. + Period 로 구간을 늘려 첨두 4분, 비첨두 8분처럼 나눌 수 있습니다. 막차가 첫차보다 이르면 자정을 넘는 구간으로 봅니다(예: 09:00 to 00:30).
  • 시각은 시간대별 칩으로 보입니다(한 줄에 한 시, 칩에는 분). 칩을 누르면 그 시각이 빠지고, 아래 칸에 HH:MM 을 넣고 Add time(또는 Enter)을 누르면 하나씩 더할 수 있습니다. 목록은 언제나 정렬되고 같은 시각은 하나만 남습니다.
  • Edit as text 를 펼치면 예전처럼 시각을 글로 붙여 넣거나 고칠 수 있습니다. 칸을 벗어나면 정렬과 중복 제거를 합니다. 형식이 틀린 토큰은 지우지 않고 경고로 보여 주며, 고치기 전에는 저장되지 않습니다.
  • Line color — the color the line is drawn in. It is saved as <Line color="#rrggbb"> in railPTline.xml, is used only for display, and is ignored by the engine. Without a color the default applies: if the line number left after removing a direction suffix (_up, _down, …) is 1–9 the Seoul Metro color of that line is used, otherwise a palette color, so 1_up and 1_down match. Reset returns to the default; Apply to … gives the opposite-direction line(s) the same color.
  • Departure times — the header shows the number of departures, first and last train, and the average (min, max) headway; below it a 24-hour strip marks every departure. The strip runs from 03:00 to 03:00 the next day.
  • Generate from headways — give each period a first train, last train and headway (min), then press Replace (new list) or Merge (add to the list). + Period adds rows, e.g. a 4-minute peak and an 8-minute off-peak. A last train earlier than the first means the period runs past midnight (e.g. 09:00 to 00:30).
  • Times are shown as chips grouped by hour (one row per hour, minutes on the chips). Click a chip to remove that time; type HH:MM and press Add time (or Enter) to add one. The list is always sorted and duplicates are dropped.
  • Edit as text opens the raw list for pasting or quick fixes; it is sorted and de-duplicated when you leave the box. Malformed tokens are kept and flagged rather than dropped, and saving fails until they are fixed.
Tip. 저장 형식은 그대로 공백으로 구분한 HH:MM 목록입니다. 00:00–29:59 를 받으며 00:00–02:59 와 24:00 이후는 자정 이후 운행으로 정렬됩니다. 생성기는 자정 이후 시각을 24:10 처럼 씁니다. 엔진은 시를 24로 나눈 나머지로 읽으므로 24:10 과 00:10 은 같은 시각입니다.
Tip. The file format is unchanged: a space-separated list of HH:MM. Accepted times are 00:00–29:59; 00:00–02:59 and anything from 24:00 sort as after-midnight service. The generator writes after-midnight times as 24:10; the engine reads hours modulo 24, so 24:10 and 00:10 are the same time.
주의. 현재 버스 노선은 배차 간격(Interval)에 따라서만 운행됩니다. 시각표에 따른 버스 운행을 지원하려면 엔진을 확장해야 합니다.
Note. Bus lines currently run on headway (Interval) only. Timetable-based bus operation needs an engine extension.

Workspace Passengers

담당 파일:Files: passenger.xml

정류장 사이의 승객 수요(승객 OD)를 편집합니다. 상단의 Pax를 누르면 열립니다. 출발·도착은 roadStation.xml의 도로 정류장이고, 수요는 시간당 승객 수입니다.

Edits passenger demand between stations (passenger OD). Open it with Pax in the top bar. Origins and destinations are road stations from roadStation.xml, and demand is passengers per hour.

  1. 지도에서 출발 정류장을 누르고 이어서 도착 정류장을 누르면 표에 한 줄이 추가됩니다. 출발을 고른 뒤 같은 정류장을 다시 누르거나 Esc를 누르면 취소됩니다. 이미 있는 쌍을 고르면 그 줄로 이동합니다.
  2. 새 줄의 수요와 도착 분포는 패널 위쪽의 New row flow / New row arrivals 값을 따릅니다. 표에서 바로 고칠 수도 있습니다. Poisson은 무작위 도착, Uniform은 일정한 간격의 도착입니다.
  3. Line 칸은 지금 편집 중인 PT 노선을 기준으로, 출발에서 도착까지 한 번에 가는 노선을 보여 줍니다. 노선이 여럿이면 첫 노선과 나머지 개수(예: Bus6-2_out +9)만 보이고, 마우스를 올리면 전체 목록이 나옵니다. Transfer는 갈아타야 한다는 뜻이고(Run에서 PaxRouteGenerator를 켜야 경로가 생깁니다), No line은 두 정류장 중 하나에 서는 노선이 없다는 뜻입니다.
  4. 정류장 목록은 Station 탭에서 편집 중인 내용을 그대로 따릅니다. 아직 저장하지 않은 새 정류장도 바로 고를 수 있고, 없는 정류장 ID를 적으면 Unknown으로 표시됩니다.
  5. 줄을 누르면 지도에서 출발(초록)과 도착(보라) 정류장이 강조됩니다. 상단의 Save로 저장합니다.
  1. Click an origin station on the map, then a destination station, to add a row. Clicking the origin again or pressing Esc cancels; picking an existing pair selects its row.
  2. New rows take their flow and arrivals from New row flow / New row arrivals at the top of the panel, and you can edit them in the table. Poisson means random arrivals, Uniform evenly spaced ones.
  3. The Line column shows, from the PT lines being edited, the lines that go from origin to destination without a change. With several, it shows the first plus a count (for example Bus6-2_out +9); hover for the full list. Transfer means a change is needed (turn on PaxRouteGenerator in Run so the routes exist); No line means no line stops at one of the two stations.
  4. The station list follows what is being edited in the Station tab, so a new stop can be used before it is saved. A station ID that does not exist is marked Unknown.
  5. Clicking a row highlights its origin (green) and destination (purple) on the map. Save with Save in the top bar.

승객 OD 매트릭스 여러 개Several passenger matrices

시간대마다 승객 수요를 다르게 주려면 승객 OD 매트릭스를 여러 개 만들어 둡니다. 패널 위쪽 줄에서 편집할 매트릭스를 고르고, 표·지도 선택·Random…·검사는 모두 지금 고른 매트릭스에 적용됩니다. 목록에는 #번호 · 이름 · 쌍 수 · 시간당 승객 수가 보입니다.

To give each time of day its own passenger demand, keep several passenger OD matrices. Pick the matrix to edit in the row at the top of the panel; the table, map picking, Random… and the checks all work on that matrix. The list shows #id · name · pairs · pax/h.

  • New는 다음 번호의 빈 매트릭스를, 복사 버튼은 지금 매트릭스를 다음 번호로 복제합니다. 휴지통 버튼은 지금 매트릭스를 지웁니다(마지막 하나는 지울 수 없습니다). 이름 칸에는 오전 첨두처럼 알아보기 쉬운 이름을 붙일 수 있습니다. 이름은 표시용이라 엔진은 읽지 않습니다.
  • 번호는 0 이상의 정수이고 겹치지 않습니다. 파일에는 매트릭스마다 <od_pax id="번호"> 블록이 번호 순으로 저장됩니다. 번호가 없는 예전 파일은 매트릭스 0으로 읽고, 그런 블록이 여럿이면 하나로 합칩니다(엔진도 전부 더해서 썼습니다).
  • 시나리오에 승객 스케줄이 없으면 엔진은 매트릭스 0을 씁니다. 시간 구간마다 다른 매트릭스를 쓰려면 Scenario 탭에서 구간별로 승객 매트릭스를 고르세요.
  • 매트릭스 추가·복제·삭제·이름 변경도 저장하기 전에는 Ctrl+Z로 되돌릴 수 있습니다.
  • New adds an empty matrix with the next id; the copy button duplicates the current matrix to the next id; the trash button deletes the current matrix (the last one cannot be deleted). The name box takes a label such as AM peak. Names are for display only; the engine ignores them.
  • Ids are non-negative whole numbers and never repeat. Each matrix is saved as an <od_pax id="N"> block, in id order. An older file without ids is read as matrix 0, and several such blocks are merged into one (the engine used to add them all up).
  • When a scenario has no passenger schedule, the engine uses matrix 0. To use a different matrix in each time segment, pick the passenger matrix per segment in the Scenario tab.
  • Adding, duplicating, deleting and renaming matrices can be undone with Ctrl+Z before you save.

랜덤 승객 OD 생성Random passenger OD

패널의 Random…은 OD Matrix의 Random Matrix와 같은 방식으로 승객 수요를 만듭니다. Generation mode(Total demand / Range per OD pair), Distribution(Uniform / Normal / Sparse), Active OD ratio, Random seed의 뜻도 같고, 같은 seed를 쓰면 같은 결과가 나옵니다. 승객 OD에만 있는 설정은 다음과 같습니다.

Random… in the panel creates passenger demand the same way OD Matrix's Random Matrix does. Generation mode (Total demand / Range per OD pair), Distribution (Uniform / Normal / Sparse), Active OD ratio and Random seed mean the same, and the same seed gives the same result. Settings that only passenger OD has:

  • Station pairs: 후보는 PT 노선이 실제로 잇는 정류장 쌍뿐입니다. Direct only는 한 노선이 출발 정류장에 섰다가 나중에 도착 정류장에 서는 쌍, Any served stations는 노선이 서는 정류장끼리의 모든 쌍입니다(갈아타는 경로가 생기도록 Run에서 PaxRouteGenerator를 켜세요).
  • Arrivals at the origin station: 생성한 줄의 도착 분포(Poisson / Uniform)입니다.
  • Put the result in: Replace는 지금 매트릭스의 줄을 지우고 새로 채우고, Add는 그대로 둔 채 더합니다(이미 있는 쌍은 수요가 합쳐집니다). New matrix는 다음 번호로 새 매트릭스를 만들어 거기에 넣습니다. 줄이 있으면 Add, 비어 있으면 Replace가 기본으로 선택됩니다. 저장하기 전에는 Ctrl+Z로 되돌릴 수 있습니다.
  • Station pairs — only pairs a PT line actually connects are candidates. Direct only takes pairs where one line stops at the origin and later at the destination; Any served stations takes every pair of stations a line stops at (turn on PaxRouteGenerator in Run so transfer routes exist).
  • Arrivals at the origin station — the arrival distribution (Poisson / Uniform) of the generated rows.
  • Put the result in — Replace clears the current matrix's rows first; Add keeps them, and a generated pair already listed adds to its flow; New matrix puts the pairs in a new matrix with the next id. Add is preselected when rows exist, Replace when the table is empty. Ctrl+Z undoes it before you save.
개별 승객 여정(agent_pax)은 그대로 남습니다. 이 편집기는 <od_pax> 블록만 바꾸고, 파일에 있던 <agent_pax>와 주석은 저장해도 유지됩니다. 파일이 없으면 저장할 때 새로 만듭니다.

담당 파일:File: detector.xml

  1. ITS 국가교통정보센터(its.go.kr)에서 표준노드링크 SHP를 내려받아 SimulationInput/nodelink/<이름>/ 폴더에 MOCT_NODE.shp/.dbf, MOCT_LINK.shp/.dbf 4개 파일을 넣어 둡니다.
  2. 상단바의 Network → Add network → Import Korean node-link → SHP set에서 폴더를 선택하면 노드·링크 수와 전체 범위가 표시됩니다.
  3. Extent에 잘라낼 영역의 좌표(EPSG:5186, m)를 입력하거나 Use full extent로 전체를 지정합니다.
  4. Preview로 네트워크를 실제로 만들지 않고 포함될 노드·링크 수를 확인하고, 폴더 이름을 정한 뒤 Import를 누릅니다. 새 네트워크 폴더가 만들어지고 바로 편집을 시작할 수 있습니다.

가져오는 동안 차로 수(LANES)·제한속도(MAX_SPD)·도로명 등의 속성이 매핑되고, 차로 기하와 교차로 커넥션은 Network 편집기와 같은 규칙으로 자동 생성됩니다.

Tip. 시·도 단위 전체 SHP에서도 bbox로 잘라내면 수 초 안에 끝납니다. 먼저 작은 영역으로 Preview를 실행해 보고 범위를 넓혀 가세요.
  1. Download the standard node-link SHP set from ITS (its.go.kr) and put the four files MOCT_NODE.shp/.dbf and MOCT_LINK.shp/.dbf into SimulationInput/nodelink/<name>/.
  2. Network → Add network → Import Korean node-link, then pick the folder under SHP set — the node and link counts and the full extent are shown.
  3. Enter the area to cut out under Extent (EPSG:5186, metres), or press Use full extent.
  4. Preview reports how many nodes and links would be included without creating anything; then name the folder and press Import — a new network folder is created and ready to edit.

During the import, attributes such as lane count (LANES), speed limit (MAX_SPD), and road name are mapped over, and lane geometry and intersection connections are generated by the same rules the Network editor uses.

Tip. Even a province-wide SHP set cuts down in seconds once you give it a bbox. Preview a small area first, then widen it.

저장 백업과 복원Backups and restore

어떤 워크스페이스든 저장할 때마다 덮어쓰기 직전의 파일이 폴더 안의 .backups/에 자동으로 보관됩니다(파일별로 최근 10개까지 보관하며, 내용이 같으면 중복해서 저장하지 않습니다).

  1. 상단바의 Network → Backups(Edit 모드)를 누르면 파일별 백업 목록이 시각·크기와 함께 표시됩니다. 현재 파일과 내용이 같은 백업은 "= current"로 표시됩니다.
  2. Diff: 선택한 백업과 현재 파일의 차이(추가/삭제 줄 수와 상세 diff)를 미리 보여 줍니다.
  3. Restore: 파일을 해당 시점으로 되돌립니다. 복원 직전의 현재 파일도 백업으로 남으므로 복원 자체를 다시 되돌릴 수 있습니다. 복원한 뒤에는 폴더를 자동으로 다시 불러옵니다.

Every save, in any workspace, first copies the file it is about to overwrite into .backups/ inside the folder (the 10 most recent per file; identical content is not stored twice).

  1. Network → Backups (Edit mode) lists the backups per file with time and size. A backup whose content matches the current file is marked "= current".
  2. Diff — preview what changed between that backup and the current file (added and removed line counts, plus the detailed diff).
  3. Restore — roll back to that point. The file as it stands is backed up first, so the restore itself can be undone. The folder reloads afterwards.

  2. Pick the file under Package file (.zip) — one exported from NextSIM, or a plain zip of a SimulationInput/networks/<name> folder.
  3. Network name is prefilled from the file name; change it if you like. Import creates SimulationInput/networks/<name>/ and opens that network.
가져오기 규칙. 이미 있는 이름은 쓸 수 없으며, 이때 오류 문구에서 사용할 수 있는 이름(예: name_2)을 알려 줍니다. 절대 경로·..·심볼릭 링크가 든 zip, zip이 아닌 파일, network.xml이 없는 패키지는 거부합니다. .xml · .json · .txt · .csv · .md 파일만 가져오고 나머지는 건너뜁니다. parameter_xml이 없는 패키지에는 기본 parameter_xml을 넣습니다. 크기 한도는 기본 1024 MB이며, 환경 변수 NEXTSIM_MAX_PACKAGE_MB로 바꿀 수 있습니다.
Import rules. The name must not exist yet; the error suggests a free one (such as name_2). Zips with absolute paths, .. or symbolic links, files that are not zips, and packages without network.xml are rejected. Only .xml · .json · .txt · .csv · .md files are taken; anything else is skipped. A package without parameter_xml gets the default parameter_xml. The size limit is 1024 MB by default; change it with the environment variable NEXTSIM_MAX_PACKAGE_MB.

다른 이름으로 저장(Save as new network…)Save as new network…

Edit 모드의 Network → Save as new network…는 현재 네트워크를 새 폴더로 복사하고 (.backups와 생성 파일은 제외), 저장하지 않은 워크스페이스를 모두 새 폴더에 저장한 뒤 새 네트워크에서 편집을 이어 갑니다. 원래 네트워크는 바뀌지 않습니다. 가져오기와 마찬가지로 이미 있는 이름은 새 이름으로 쓸 수 없습니다.

Network → Save as new network… (Edit mode) copies the current network to a new folder (without .backups and generated files), saves every unsaved workspace into the new folder, and carries on editing the new network. The original network is not changed. As with an import, the new name must not exist yet.

워크스페이스마다 무엇을 클릭할 수 있나요?What is clickable in each workspace?

워크스페이스마다 그곳에서 쓰는 오브젝트만 클릭·호버에 반응합니다. 다른 오브젝트를 편집하려면 해당 워크스페이스로 이동하세요.

Each workspace responds only to the objects it uses. To edit something else, switch to the workspace that owns it.

큰 네트워크를 열면 느리지 않나요?Is a large network slow to work with?

네트워크는 규모와 관계없이 항상 캔버스로 그려집니다. 뷰포트 컬링과 배율별 LOD를 사용하므로 그리는 양이 화면 크기에만 비례하고, 링크가 수만 개인 규모까지 부드럽게 동작합니다. (예전에는 링크 800개를 기준으로 SVG와 캔버스 중 하나를 골랐지만, 그보다 작은 규모에서도 DOM 요소가 수천 개에 이르러 화면이 끊겼기 때문에 이 기준을 없앴습니다.)

The network is always drawn on canvas, regardless of size. With viewport culling and zoom-based level of detail, the amount drawn scales with the screen rather than the network, and it stays smooth into the tens of thousands of links. (There used to be an 800-link SVG/canvas threshold, but even below it a few thousand DOM elements stuttered, so the threshold was removed.)

렌더 차이를 확인해야 할 때만 브라우저 콘솔에서 localStorage.setItem('nextsim-network-canvas','off')로 예전 SVG 렌더링 방식을 켤 수 있습니다. 'on'을 설정하는 것은 이제 의미가 없습니다. 기본값이 이미 캔버스이기 때문입니다.

For debugging a rendering difference you can force the old SVG path from the console with localStorage.setItem('nextsim-network-canvas','off'). Setting it to 'on' does nothing now — canvas is already the default.

편집할 때 화면이 깜빡이지 않나요?Does the map flicker while editing?

아닙니다. 예전에는 링크·노드를 고칠 때마다 렌더러를 통째로 다시 만들어 화면이 잠깐 비었지만, 지금은 카메라를 유지한 채 제자리에서 갱신합니다. 캔버스는 기존 그림을 그대로 둔 채 한 프레임 안에 새 그림으로 덮어 그리며, 줌·위성 배경·이벤트 바인딩도 그대로 유지됩니다. 그 결과 큰 네트워크에서도 편집 내용이 더 빠르게 반영됩니다.

No. Editing used to rebuild the whole renderer, briefly blanking the map; now it refreshes in place with the camera intact — the canvas keeps its current pixels until the new frame overwrites them, and the zoom, basemap, and event bindings stay alive. Edits also apply faster on large networks as a result.

저장·오류 메시지는 어디에 뜨나요?Where do save and error messages appear?

모두 화면 우측 상단 토스트로 표시됩니다. 패널 안에는 실시간 상태 문구를 표시하지 않으며, 같은 메시지가 반복되면 한 번만 보여 줍니다. 다만 위성 배경의 정합 상태는 예외적으로 Display 패널 안에 표시됩니다.

All of them as a toast in the top-right corner. The panels no longer carry a live status line, and repeats of the same message are shown once. The one exception is the basemap georeference status, which stays inside the Display panel.

에디터에 없는 XML 속성은 저장하면 사라지나요?Are XML attributes the editor doesn't show lost on save?

아니요. qmax, wave_spd처럼 에디터 화면에 노출되지 않는 속성도 저장할 때 원본 그대로 보존됩니다.

No. Attributes that never appear in the UI — qmax, wave_spd, and the like — are preserved verbatim on save.

워크스페이스끼리 참조가 어긋나면?What if references between workspaces break?

저장할 때 다른 워크스페이스가 참조하는 ID(예: PT 노선이 참조하는 링크, 신호가 참조하는 노드)가 사라지면 경고 알림을 표시합니다. 삭제나 분할을 한 뒤에는 관련 워크스페이스를 한 번 확인하는 것이 좋습니다.

Saving warns you when an ID another workspace references disappears — a link a PT line uses, a node a signal points at. After deleting or splitting, it is worth checking the related workspaces once.

지도가 이동하지 않거나 클릭이 이상하게 동작합니다The map won't pan, or clicks behave oddly

  • 화면을 이동하려면 Space를 누른 채 왼쪽 버튼으로 드래그(또는 가운데 버튼으로 드래그)합니다. Space를 누르지 않은 좌클릭 드래그는 편집 동작(박스 선택 등)에 배정되어 있습니다. 마우스가 지도 위에 있을 때 Space를 누르세요.
  • 측정 도구(📏)가 켜져 있으면 클릭할 때마다 측정점이 추가됩니다. Esc로 측정 도구를 끄세요.
  • Network의 편집 모드가 켜져 있으면 Esc로 해제한 뒤 Select(V)로 돌아오세요.
  • OD에서 source 선택 모드가 켜져 있으면 링크를 클릭할 때 진입점이 토글됩니다. 아래쪽 바의 Done을 누르거나 Esc를 눌러 선택 모드를 끝내세요.
  • Pan by holding Space and left-dragging (or with the middle button) — left-drag without Space is bound to editing (box select and so on). Press Space while the pointer is over the map.
  • With the measure tool (📏) on, every click adds a measuring point. Esc turns it off.
  • If a Network edit mode is active, press Esc and return to Select (V).
  • In OD, source pick mode makes link clicks toggle entry points — finish it with Done in the bottom bar or Esc.

편집한 내용으로 시뮬레이션을 실행하려면?How do I run a simulation with my edits?

상단바의 Run을 눌러 전환합니다. 저장하지 않은 변경 사항이 있으면 Save & switch로 저장하면서 전환합니다(Run 모드로 전환). 같은 네트워크가 Run 모드로 열리면 Simulation 패널에서 시나리오를 고르고 Run Selected Network를 누르면 됩니다. 결과 재생·분석 방법은 Run 모드 가이드를 보세요.

Switch with Run in the top bar — if anything is unsaved, Save & switch saves it on the way (Switching to Run mode). The same network opens in Run mode; pick a scenario in the Simulation panel and press Run Selected Network. For replaying and analysing the result, see the Run mode guide.
