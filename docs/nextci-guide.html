NextCI 시작하기NextCI: getting started

NextCI는 NextSIM 엔진을 TCP로 외부에서 제어하는 인터페이스입니다. Python에서 시뮬레이션을 원하는 만큼 진행하고, 차량·링크·검지기 상태를 읽고, 같은 시점으로 되돌려 여러 시도를 비교할 수 있습니다. 강화학습, 공동 시뮬레이션, 제어 실험처럼 프로그램 안에서 시뮬레이션을 다뤄야 할 때 사용합니다.

NextCI is the interface for driving the NextSIM engine from outside over TCP. From Python you advance the simulation as far as you want, read vehicle, link, and detector state, and rewind to the same moment to compare attempts. Use it when a program has to hold the simulation: reinforcement learning, co-simulation, control experiments.

NextCI란What NextCI is

엔진은 별도 프로세스(UnitTestsAPI)로 실행되고, Python 패키지 nextci가 TCP로 명령을 보냅니다. Python 안에서 실행되는 시뮬레이터가 아니라 C++ 프로세스를 원격으로 제어하는 구조입니다.

The engine runs as a separate process (UnitTestsAPI), and the Python package nextci sends it commands over TCP. It is not a simulator running inside Python; it remote-controls a C++ process.

Python · nextci→ TCP :9999 →UnitTestsAPI→SimulationInput / SimulationOutput

아직 신호·차량·수요를 바꾸는 API는 없습니다. 현재 NextCI는 조회와 시뮬레이션 제어를 중심으로 하며, 바꿀 수 있는 대상은 링크 모드와 검지기뿐입니다. 자세한 내용은 아직 지원하지 않는 기능을 보세요.
There is no API yet for changing signals, vehicles, or demand. NextCI today is mostly queries plus simulation control; what you can change is link mode and detectors. See Not yet supported.

준비Setup

NextCI 서버(UnitTestsAPI)는 Windows 설치 파일과 Linux · WSL 배포판에 포함되어 있지 않습니다. 소스에서 빌드한 환경이 필요합니다.

The NextCI server (UnitTestsAPI) is not in the Windows installer or the Linux · WSL package. You need a build from source.

  1. 서버를 빌드합니다. 실행 파일은 build/captain/release/bin/UnitTestsAPI에 생성됩니다.
  2. Python 패키지를 설치합니다. 외부 의존성은 없습니다.
  3. Python 런처에 서버 위치를 알려 줍니다. 런처가 기본으로 찾는 경로(Captain/build/bin 등)에는 프리셋 빌드 경로가 포함되어 있지 않으므로 환경 변수 NEXTSIM_UNIT_TESTS_API로 지정합니다.
  1. Build the server. It lands in build/captain/release/bin/UnitTestsAPI.
  2. Install the Python package. It has no external dependencies.
  3. Tell the Python launcher where the server is. Its default search paths (Captain/build/bin and so on) do not include the preset build, so set NEXTSIM_UNIT_TESTS_API.
# 1
cmake --build build/captain/release --target UnitTestsAPI -j

# 2
python3 -m pip install -e NextCI

# 3
export NEXTSIM_UNIT_TESTS_API="$PWD/build/captain/release/bin/UnitTestsAPI"

실행되는 네트워크Which network runs

서버는 작업 폴더에서 상위 폴더로 올라가며 SimulationInput/config.txt를 찾고, 그 파일에 적힌 network(SimulationInput/networks/<network>/)를 실행합니다. 경로 파일 (Route.json 등)이 있어야 하므로, 처음 쓰는 네트워크는 Simulation 화면에서 한 번 실행하거나 RouteGenerator를 먼저 실행해 두세요. 다른 데이터 폴더를 쓰려면 NEXTSIM_SERVER_CWD에 그 폴더를 지정합니다.

The server walks up from its working directory looking for SimulationInput/config.txt and runs the network it names (SimulationInput/networks/<network>/). Route files (Route.json and so on) must exist, so for a new network run it once from the Simulation page or run RouteGenerator first. To use another data folder, point NEXTSIM_SERVER_CWD at it.

서버도 결과 DB를 덮어씁니다. SimulationOutput/simulation_output.db가 NextCI 세션의 기록으로 바뀝니다. 보관할 결과는 먼저 다른 곳으로 옮기거나, 별도 데이터 폴더(NEXTSIM_SERVER_CWD)를 사용하세요.
The server rewrites the result database too. SimulationOutput/simulation_output.db becomes the NextCI session's record. Move any result you want to keep first, or use a separate data folder (NEXTSIM_SERVER_CWD).

첫 연결First connection

launch_and_connect()는 서버를 실행하고, 서버가 준비될 때까지 기다린 뒤 연결합니다. with 블록을 벗어나면 연결을 닫고 서버도 종료합니다.

launch_and_connect() starts the server, waits until it is ready, and connects. Leaving the with block closes the connection and stops the server.

from nextci import NextCIClient

with NextCIClient(port=9999).launch_and_connect() as client:
    print(client.get_version())                 # NextSim-NextCI/0.1
    print(client.get_total_cycle())             # 6000  (10 min scenario)
    print(client.sim_step(1000))                # cycle=1000;finished=0
    print(client.get_vehicle_count())           # 313

    client.save_checkpoint("t0")
    client.sim_step(300)                        # 382 vehicles now
    print(client.restore_checkpoint("t0"))      # cycle=1000;finished=0
    print(client.get_vehicle_count())           # 313 again

주석에 적힌 값은 예제 네트워크 bucheon의 시나리오 0에서 얻은 결과입니다. 네트워크와 시나리오에 따라 값이 달라집니다.

The values in the comments come from scenario 0 of the example network bucheon; they depend on the network and scenario.

서버 실행 방식How the server runs

기본 방식은 ServeOnce입니다. 클라이언트 하나가 연결했다가 끊으면 서버 프로세스도 종료됩니다. 여러 번 연결하려면 서버를 --serve-loop 옵션으로 직접 실행하고 connect()만 사용합니다.

The default is ServeOnce: when one client connects and disconnects, the server process ends. To connect repeatedly, start the server yourself with --serve-loop and only call connect().

# terminal 1
build/captain/release/bin/UnitTestsAPI --port 9999 --serve-loop

# Python
client = NextCIClient(port=9999).connect()

시간과 스텝Time and steps

시간 단위는 사이클이며, 1사이클은 0.1초입니다. sim_step(n)은 n 사이클을 진행하고 cycle=…;finished=… 형식의 문자열을 반환합니다. 시나리오가 끝나는 시점은 get_total_cycle()과 is_finished()로 확인할 수 있습니다.

Time is counted in cycles; one cycle is 0.1 s. sim_step(n) advances n cycles and returns a string of the form cycle=…;finished=…. The end of the scenario is given by get_total_cycle() and is_finished().

with NextCIClient().launch_and_connect() as client:
    while not client.is_finished():
        client.sim_step(50)                      # 5 s
        speed = client.get_link_mean_speed_mps(20000402)
        ...
검지기 구간 값은 flush 뒤에 읽습니다. 검지기의 구간 집계(교통량, 점유율 등)는 sim_step() 다음에 flush_recordings()를 호출해야 갱신됩니다.
Flush before reading detector intervals. Interval aggregates (flow, occupancy, and so on) update after sim_step() followed by flush_recordings().

상태 조회Querying state

시뮬레이션 · 차량 · 링크 · 차로 · Meso 셀 · 검지기 상태를 읽는 메서드는 80개가 넘습니다. 영역별 목록과 각 메서드의 인자 · 반환값 · 조건 · 비용은 API 레퍼런스에 정리되어 있고, 한눈에 보기 표에서 전체를 한 번에 훑어볼 수 있습니다.

There are more than 80 methods for reading the simulation, vehicles, links, lanes, meso cells, and detectors. The list by area, with each method's arguments, returns, conditions, and costs, is in the API reference; the at-a-glance table shows them all at once.

차량 수는 micro 차로에 있는 차량만 셉니다. get_vehicle_count()와 get_link_*는 meso 셀 안의 차량을 세지 않습니다. 링크를 meso로 바꾸면 그 링크의 차량은 셀로 옮겨지므로 get_meso_cell_vehicle_count()로 세어야 합니다.
Vehicle counts cover micro lanes only. get_vehicle_count() and get_link_* do not count vehicles inside meso cells. When a link switches to meso its vehicles move into cells and are counted with get_meso_cell_vehicle_count().

Meso 조회와 모드 전환Meso queries and mode switching

Meso 셀 값은 그 링크가 현재 meso 모드일 때만 읽을 수 있습니다. micro 모드로 실행 중인 링크의 셀을 조회하면 Meso cell not found or currently in micro mode 오류가 발생합니다. 필요하면 set_link_mode()로 링크 하나를 meso로 바꾼 뒤 시뮬레이션을 조금 진행하고 값을 읽습니다.

Meso cell values can be read only while that link is in meso mode. Asking for a cell of a link running micro fails with Meso cell not found or currently in micro mode. If needed, switch the link with set_link_mode(), advance a little, then read.

links = client.get_meso_link_id_list()          # links that have meso topology
link = links[0]
client.set_link_mode(link, "meso")
client.sim_step(50)                              # meso updates every 5 s
print(client.get_meso_section_count(link))
print(client.get_meso_cell_density_veh_per_km(link, 0, 0))
조회 비용. 대수 · 속도 · 밀도는 사이클마다 캐시되어 조회 부담이 적지만, get_meso_cell_vehicle_id_list()는 대기열을 순회하며 목록을 복사하므로 필요할 때만 사용하세요.
Query cost. Count, speed, and density are cached per cycle and cheap; get_meso_cell_vehicle_id_list() walks the queue and copies a list, so use it only when you need it.

검지기Detectors

입력 파일에 정의된 검지기 외에도 세션 중에 검지기를 추가할 수 있습니다. E1은 한 지점, E2는 차로 위의 한 구간, E3는 진입 · 진출 지점으로 둘러싼 영역입니다.

Besides the detectors in the input files, you can attach more during a session. E1 is a point, E2 a stretch of one lane, E3 an area bounded by entry and exit points.

link = 20001453                                  # 3 lanes, 243.9 m
client.add_detector_e1(detector_id="e1_a", link_id=link, lane_index=0, pos=120.0, freq=60.0)
client.add_detector_e3(
    detector_id="e3_a",
    entries=f"{link}:0:5.0,{link}:1:5.0,{link}:2:5.0",        # link:lane:pos, …
    exits=f"{link}:0:238.0,{link}:1:238.0,{link}:2:238.0",
)
client.sim_step(600)                             # 60 s
client.flush_recordings()
print(client.get_detector_flow("e1_a"))          # 120.0 veh/h
print(client.get_detector_mean_travel_time("e3_a"))
client.remove_detector("e3_a")

링크 20001453과 교통량 값은 예제 네트워크 bucheon 기준입니다. 사용하는 네트워크의 ID로 바꾸세요. ID는 get_link_id_list()나 Editor의 Network 워크스페이스에서 확인할 수 있습니다. 존재하지 않는 링크를 지정해도 검지기는 추가되지만, enabled=0으로 등록되어 값이 쌓이지 않습니다. 반환된 payload로 확인하세요.

Link 20001453 and the flow value are from the example network bucheon; use IDs from your own network (get_link_id_list(), or the Editor's Network workspace). A detector on a link that does not exist is still added, but with enabled=0, so it never records; check the returned payload.

체크포인트Checkpoints

체크포인트는 서버 메모리에 시뮬레이션 상태를 저장합니다. 복원할 때 엔진을 다시 시작하지 않고 저장한 사이클로 바로 돌아가므로, 같은 시점에서 여러 정책을 시험할 때 사용합니다. ID를 다르게 지정하면 체크포인트를 여러 개 함께 보관할 수 있습니다.

A checkpoint stores the simulation state in the server's memory. Restoring does not restart the engine; it returns to the saved cycle in place, so you can try several policies from the same moment. Different IDs coexist.

client.sim_step(1000)
client.save_checkpoint("episode_start")

client.sim_step(200)                    # try policy A
a = client.get_vehicle_count()
client.restore_checkpoint("episode_start")

client.sim_step(200)                    # try policy B from the same state
b = client.get_vehicle_count()
저장되는 것내용
P0사이클, 차량 ID 카운터, 링크의 차량(micro 차로 + 모든 meso 차로·셀 대기열), 차로·셀별 신호 상태, 모드 시퀀스
P1검지기 집계 상태
P2출발지 · 차고지 예약과 대기열, 도착지 대기열

난수 상태는 저장되지 않습니다. 복원한 직후의 사이클 · 차량 수 · 차량 ID는 저장 시점과 같지만, 그 뒤로 더 진행하면 중단 없이 실행한 경우와 결과가 달라질 수 있습니다. 같은 상태에서 새 행동을 시험하는 용도로는 충분하지만, 궤적을 비트 단위까지 재현하는 용도에는 적합하지 않습니다. 체크포인트는 세션이 끝날 때까지 메모리에 남으며 개수 제한이 없습니다.
Random-number state is not saved. At the moment of restore the cycle, vehicle count, and vehicle IDs match the save, but stepping further can diverge from an uninterrupted run. That is enough for trying new actions from the same state, not for bit-identical trajectory replay. Checkpoints stay in memory until the session ends, with no count limit.

예전의 save_state() / load_state()는 디스크의 Vehicle.json을 사용하며, 불러오면 엔진을 다시 시작하므로 사이클이 0이 됩니다. 제어 루프에는 체크포인트를 사용하세요.

The older save_state() / load_state() use Vehicle.json on disk, and loading restarts the engine with the cycle back at 0. Use checkpoints in control loops.

객체 ID는 링크가 linkId, 차로가 linkId:laneIndex, Meso 셀이 linkId:laneIndex:cellIndex입니다. SUBSCRIBE (0x03)과 UNSUBSCRIBE(0x04)는 ID만 예약되어 있습니다.

Object IDs are linkId for links, linkId:laneIndex for lanes, and linkId:laneIndex:cellIndex for meso cells. SUBSCRIBE (0x03) and UNSUBSCRIBE (0x04) are reserved only.

문제 해결Troubleshooting

UnitTestsAPI binary not foundUnitTestsAPI binary not found

서버를 빌드했는지, 그리고 NEXTSIM_UNIT_TESTS_API가 그 실행 파일을 가리키는지 확인하세요(준비 3단계). launch_and_connect(binary_path=…)로 경로를 직접 지정할 수도 있습니다.

Check that the server is built and that NEXTSIM_UNIT_TESTS_API points at it (Setup, step 3). You can also pass launch_and_connect(binary_path=…).

Port 9999 is already in usePort 9999 is already in use

이전에 실행한 서버가 아직 남아 있습니다. 그 서버를 종료하거나(pkill -f "UnitTestsAPI --port 9999") 다른 포트를 사용하세요(NextCIClient(port=10000)).

An earlier server is still running. Stop it (pkill -f "UnitTestsAPI --port 9999") or use another port (NextCIClient(port=10000)).

링크 목록에 있는 ID인데 Link not found 오류가 납니다An ID from the link list gives Link not found

get_link_id_list()에는 교차로 내부 링크(예제 네트워크에서는 100004210 같은 9자리 ID)도 들어 있는데, 이 링크들은 get_link_* 개별 조회를 지원하지 않습니다. NextCIStatusError 예외를 잡아 해당 링크를 건너뛰세요.

get_link_id_list() also lists intersection-internal links (nine-digit IDs such as 100004210 in the example network), and these do not support per-link get_link_* queries. Catch NextCIStatusError and skip them.

두 번째 연결이 실패합니다A second connection fails

기본 ServeOnce 서버는 첫 클라이언트의 연결이 끊기면 종료됩니다. 여러 번 연결하려면 --serve-loop 옵션으로 서버를 실행하세요.

The default ServeOnce server ends when the first client disconnects. To connect again and again, start it with --serve-loop.

Meso cell not found or currently in micro modeMeso cell not found or currently in micro mode

그 링크가 현재 micro 모드로 실행되고 있습니다. Meso 조회와 모드 전환을 보세요.

That link is currently running micro. See Meso queries and mode switching.

검지기 값을 읽으면 오류가 납니다Reading a detector value fails

아직 구간 기록이 없어서 생기는 오류입니다. sim_step()으로 집계 주기(freq) 이상 진행하고 flush_recordings()를 호출한 뒤 값을 읽으세요.

No interval has been recorded yet. Step past the aggregation interval (freq), call flush_recordings(), then read.

아직 지원하지 않는 기능Not yet supported

  • 제어 API: 신호 현시, 차량 생성 · 삭제 · 속도, 경로, 수요를 바꾸는 명령은 아직 없습니다.
  • 난수 상태 체크포인트: 복원 뒤 궤적을 그대로 재현하는 데 필요하며, 아직 계획 단계입니다.
  • 체크포인트 개수 제한: 아직 제한이 없어 세션이 끝날 때까지 모든 체크포인트가 메모리에 남습니다.
  • 구독(SUBSCRIBE): 명령 ID만 예약되어 있습니다.
  • Control APIs — there are no commands yet for signal phases, spawning or removing vehicles, speeds, routes, or demand.
  • RNG in checkpoints — needed for exact replay after restore; planned only.
  • Checkpoint limits — every checkpoint stays in memory until the session ends.
  • Subscriptions — the command IDs are reserved only.
