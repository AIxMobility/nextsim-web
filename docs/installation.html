설치Installation

NextSIM 은 시뮬레이션 엔진과 브라우저 도구(Editor · Simulation)를 한 번에 설치합니다. 설치 방법은 네 가지이고, 어느 방법이든 끝나면 브라우저에서 같은 화면이 열립니다. 사용 환경에 맞는 방법 하나만 고르면 됩니다.

Installing NextSIM gives you the simulation engine and the browser tools (Editor and Simulation) together. There are four ways to install; every one of them ends with the same screen in your browser, so pick one that fits your machine.

공통 요구 사항: AVX2 를 지원하는 x86-64 CPU. 2013년(Intel Haswell) 이후의 인텔·AMD CPU 는 대부분 해당합니다. ARM 기기(Apple Silicon Mac, Snapdragon 노트북 등)에서는 현재 실행되지 않습니다.
Every method needs an x86-64 CPU with AVX2. Almost every Intel or AMD CPU since 2013 (Intel Haswell) qualifies. ARM machines — Apple Silicon Macs, Snapdragon laptops — are not supported today.

Windows 설치 파일Windows installer

NextSim-Setup-v1.1.exe Windows 10/11 64비트 · Edge 또는 ChromeWindows 10/11 64-bit · Edge or Chrome

  1. 릴리스 페이지에서 NextSim-Setup-v1.1.exe 를 내려받습니다.
  2. 설치 파일을 실행하고 안내에 따라 설치합니다. Python 과 시뮬레이터가 모두 들어 있어 따로 설치할 것은 없습니다.
  3. 시작 메뉴나 바탕 화면의 NextSim 을 실행합니다. 검은 콘솔 창이 열리고 몇 초 뒤 NextSim 창(브라우저)이 뜹니다.
  4. 첫 시뮬레이션으로 넘어갑니다.
  1. Download NextSim-Setup-v1.1.exe from the releases page.
  2. Run it and follow the installer. Python and the simulator are bundled, so there is nothing else to install.
  3. Launch NextSim from the Start menu or the desktop. A black console window opens, and a few seconds later the NextSim window (your browser) appears.
  4. Continue with your first simulation.
콘솔 창이 곧 서버입니다. 이 창을 닫으면 NextSim 이 종료됩니다. 서버는 이 PC 안에서만 접속할 수 있고(http://127.0.0.1:8000/, 사용 중이면 다음 빈 포트), 실제 주소는 콘솔 창 상단에 표시됩니다.
The console window is the server. Closing it quits NextSim. The server only accepts connections from this PC (http://127.0.0.1:8000/, or the next free port), and the address it settled on is printed at the top of the console.
"Windows 의 PC 보호" 창이 뜨면 추가 정보 → 실행을 누르세요. 서명되지 않은 설치 파일에 Windows SmartScreen 이 보이는 경고입니다.
If "Windows protected your PC" appears, choose More info → Run anyway. It is SmartScreen's warning for an unsigned installer.

Docker

Dockerfiledocker-compose.yml Windows · macOS(Intel) · LinuxWindows · macOS (Intel) · Linux

Docker Desktop 만 있으면 컴파일러 없이 저장소에서 바로 띄울 수 있습니다. 첫 실행은 엔진을 컨테이너 안에서 빌드하므로 몇 분 걸립니다.

With Docker Desktop you can start straight from the repository without a local compiler. The first start builds the engine inside the container, so it takes a few minutes.

소스 저장소 접근 권한이 필요합니다. NextSIM 소스 저장소는 현재 비공개라, 아래 git clone 은 권한을 받은 계정에서만 됩니다. 권한 없이 쓰려면 Windows 설치 파일이나 Linux · WSL 배포판을 쓰거나, 연구실로 문의해 주세요.

데이터는 호스트의 ./workspace/ 에 남습니다 (SimulationInput/, SimulationOutput/). 컨테이너를 처음 띄울 때 예제 네트워크가 채워지고, 다른 위치를 쓰려면 NEXTSIM_WORKSPACE=~/nextsim-data docker compose up 처럼 지정합니다.

Data stays on the host in ./workspace/ (SimulationInput/, SimulationOutput/). The demo networks are copied in the first time the container starts; to use another location run NEXTSIM_WORKSPACE=~/nextsim-data docker compose up.

Linux · WSL 배포판Linux · WSL package

nextsim-linux-x64-v1.1.zip Linux x86-64 또는 Windows + WSL2 · Python 3.9+Linux x86-64 or Windows + WSL2 · Python 3.9+

미리 빌드된 실행 파일과 예제 네트워크를 묶은 ZIP 입니다. 실행 파일이 완전 정적 링크되어 있어 리눅스 배포판 버전을 가리지 않으며, git·cmake·컴파일러·Docker 가 필요 없습니다.

A ZIP of prebuilt binaries and example networks. The binaries are fully statically linked, so any Linux distribution works, and you need no git, cmake, compiler, or Docker.

  1. 릴리스 페이지에서 nextsim-linux-x64-v1.1.zip 을 내려받아 풉니다. WSL 이라면 Windows 폴더 (/mnt/c/...)보다 WSL 홈(~/) 안에 푸는 것이 몇 배 빠릅니다.
  2. Python 이 없다면 설치합니다 (Ubuntu/WSL: sudo apt install python3 python3-venv).
  3. 실행 권한을 주고 시작 스크립트를 실행합니다. 처음에는 Flask 를 내려받느라 1~2분 걸리고, 다음부터는 바로 뜹니다. 브라우저가 자동으로 열립니다.
  1. Download nextsim-linux-x64-v1.1.zip from the releases page and unpack it. On WSL, unpacking inside your WSL home (~/) is several times faster than under a Windows folder (/mnt/c/...).
  2. Install Python if you don't have it (Ubuntu/WSL: sudo apt install python3 python3-venv).
  3. Mark the scripts executable and run the start script. The first run spends a minute or two fetching Flask; after that it starts immediately. Your browser opens on its own.
cd nextsim-linux-x64-v1.1
chmod +x start_web.sh scripts/*.sh Captain/build/bin/*
./start_web.sh

Windows 에서는 start_web.bat 을 더블클릭하면 WSL 안에서 start_web.sh 가 실행됩니다. WSL 이 없다면 PowerShell(관리자)에서 wsl --install 후 재부팅하고, Ubuntu 를 한 번 열어 초기 설정을 마친 뒤 다시 실행하세요. 종료는 터미널에서 Ctrl+C.

On Windows, double-click start_web.bat to run start_web.sh inside WSL. Without WSL, run wsl --install in an administrator PowerShell, reboot, open Ubuntu once to finish its setup, then try again. Stop the server with Ctrl+C in the terminal.

데이터를 배포판 밖에 두기Keeping data outside the package

데이터 폴더를 따로 두면 새 버전 ZIP 으로 갈아타도 네트워크와 결과가 그대로 남습니다.

With a separate data folder, your networks and results survive an upgrade to a newer ZIP.

cp -r SimulationInput ~/nextsim-data/          # to start from the examples

엔진 빌드Building the engine

저장소를 받고 서브모듈까지 가져온 뒤 프리셋으로 빌드합니다.

Clone the repository with its submodules, then build with the preset.

# 1. 소스 받기 (서브모듈 포함)
git clone --recursive https://github.com/AIxMobility/NextSim.git
cd NextSim

# 이미 --recursive 없이 받아 뒀다면
git submodule update --init --recursive

# 2. 빌드 (저장소 루트에서)
cmake --preset release --fresh -S Captain
cmake --build build/captain/release -j
# 1. Get the source, submodules included
git clone --recursive https://github.com/AIxMobility/NextSim.git
cd NextSim

# If you already cloned without --recursive
git submodule update --init --recursive

# 2. Build, from the repository root
cmake --preset release --fresh -S Captain
cmake --build build/captain/release -j

결과 바이너리는 build/captain/release/bin/ 에 생깁니다. 웹 서버가 기본으로 찾는 위치가 바로 여기이므로, 이 경로로 빌드하면 별도 설정 없이 Simulation 의 실행 버튼이 동작합니다.

The binaries land in build/captain/release/bin/. That is exactly where the web server looks by default, so building this way makes the Simulation's run button work with no further configuration.

프리셋은 debug, release, relwithdebinfo 세 가지입니다. 특정 바이너리만 필요하면 타깃을 지정하세요:

Three presets exist: debug, release, and relwithdebinfo. To build just one binary, name the target:

cmake --build build/captain/release --target UnitTestsSimulation -j
README 의 빌드 방법은 오래됐습니다. cd Captain && cmake . && make 는 소스 트리 안에 빌드 산출물을 만들고(Captain/bin/), 웹 서버는 그 경로를 보지 않습니다. 위의 프리셋 방식을 쓰세요.
The README's build recipe is out of date. cd Captain && cmake . && make builds in-source into Captain/bin/, which the web server never reads. Use the preset workflow above.
서브모듈 주의. NextSim_io 는 .gitmodules 에 main 으로 적혀 있지만 실제 고정된 커밋은 publictransit 브랜치에 있습니다. 그래서 git submodule update --remote 는 쓰지 마세요 — 잘못된 브랜치를 가져옵니다. --init --recursive 로 고정된 커밋을 그대로 받으면 됩니다.
A submodule caveat. .gitmodules lists main for NextSim_io, but the pinned commit lives on publictransit. Avoid git submodule update --remote, which would fetch the wrong branch — use --init --recursive to take the pinned commits as they are.

웹 서버 실행Running the web server

cd NextSim
./start_visualizer.sh

Flask 가 없으면 스크립트가 설치하고, 포트가 사용 중이면 비어 있는 포트를 찾아 올립니다. 직접 실행하려면 python3 web_server.py 도 됩니다.

The script installs Flask if it is missing and, if the port is busy, scans upward for a free one. You can also run python3 web_server.py directly.

웹 UI 는 엔진을 빌드하지 않습니다. Simulation 의 실행 버튼은 이미 빌드된 바이너리를 쓸 뿐이며, 없으면 그 사실을 알리고 멈춥니다. 소스를 고쳤다면 직접 다시 빌드하세요 — 또는 NEXTSIM_WEB_BUILD=1 로 자동 빌드를 켜면 됩니다.
The web UI does not build the engine. The Simulation's run button uses the binaries that are already there and stops with a message if one is missing. Rebuild yourself after changing the source — or set NEXTSIM_WEB_BUILD=1 to have it build first.

  2. In the Run panel choose a Target scenario and press Run Selected Network. Route generation through result loading runs on its own; this small example finishes in seconds.

포트와 환경 변수Ports and environment variables

시작 스크립트(start_web.sh, start_visualizer.sh)가 읽는 변수입니다. Windows 설치판은 포트·workspace 를 스스로 정하므로 WEB_PORT, NEXTSIM_WORKSPACE, NEXTSIM_KEEP_EVENT_DBS 정도만 의미가 있습니다.

These are read by the start scripts (start_web.sh, start_visualizer.sh). The Windows build picks its own port and workspace, so only WEB_PORT, NEXTSIM_WORKSPACE, and NEXTSIM_KEEP_EVENT_DBS matter there.

"Illegal instruction" 이 나거나 실행 파일이 바로 죽습니다"Illegal instruction", or the engine dies immediately

CPU 가 AVX2 를 지원하지 않는 경우입니다. Linux 에서는 grep -o 'avx2' /proc/cpuinfo | head -1 로 확인할 수 있습니다. 소스 빌드라면 이 플래그는 Captain/CMake/CompileOptions.cmake 에 고정되어 있어 직접 손봐야 합니다.

Your CPU lacks AVX2; on Linux check with grep -o 'avx2' /proc/cpuinfo | head -1. For a source build the flag is hard-coded in Captain/CMake/CompileOptions.cmake, so you have to edit that file yourself.

Run 이 "실행 파일이 없습니다" 로 실패합니다Run fails with "executable not found"

Windows: 설치 폴더의 engine\ 안에 exe 3개가 있는지, 백신이 격리하지 않았는지 확인하세요. ZIP: Captain/build/bin/ 에 실행 파일 3개가 있고 실행 권한이 있는지 확인하세요. 소스 빌드: 웹 UI 는 엔진을 빌드하지 않습니다. 결과가 build/captain/release/bin/ 에 있는지 보고, 다른 곳에 빌드했다면 NEXTSIM_BIN_DIR 로 알려 주세요.

Windows: check that the three exe files are in the install folder's engine\ and that antivirus has not quarantined them. ZIP: check that the three binaries are in Captain/build/bin/ and executable. Source build: the web UI does not build for you — check the output is in build/captain/release/bin/, or point NEXTSIM_BIN_DIR at where you built.

WSL 에서 localhost 로 접속이 안 됩니다localhost doesn't work on WSL

시작 스크립트가 기동 시 이를 감지해 WSL 포워딩 설정을 자동으로 고치려 시도합니다. 그래도 안 되면 터미널에 표시된 http://<IP>:8000/ 주소로 접속하거나, Windows 쪽에서 wsl --shutdown 후 다시 시작하세요.

The start script detects this and tries to repair WSL's forwarding configuration. If it persists, use the http://<IP>:8000/ address printed in the terminal, or run wsl --shutdown from Windows and start again.

File I/O under /mnt/c/... is very slow. Move the NextSIM folder under ~/.

포트 8000 이 이미 사용 중입니다Port 8000 is already in use

기본 설정이면 빈 포트를 자동으로 찾아 올라가고, 실제 주소는 기동 로그에 표시됩니다. 포트를 직접 정하려면 WEB_PORT=8100 ./start_web.sh.

By default it scans for a free port and prints the address it settled on. To choose one yourself: WEB_PORT=8100 ./start_web.sh.

경고 때문에 빌드가 멈춥니다 (소스 빌드)A warning stops the build (source build)

-Werror 가 기본이라 경고가 곧 오류입니다. 컴파일러 버전이 달라 새 경고가 나는 경우라면 CMake 옵션 CUBBYFLOW_WARNINGS_AS_ERRORS=OFF 로 끌 수 있습니다.

Warnings are errors by default. If a different compiler version raises new ones, turn it off with the CMake option CUBBYFLOW_WARNINGS_AS_ERRORS=OFF.

The submodules are not checked out. Run git submodule update --init --recursive. Do not add --remote; it would fetch a different branch instead of the pinned commit.
