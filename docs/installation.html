설치Installation

NextSIM을 설치하면 시뮬레이션 엔진과 브라우저 도구(Run · Edit 모드를 갖춘 NextSIM 화면)가 함께 설치됩니다. 설치 방법은 네 가지이고, 어느 방법으로 설치하든 브라우저에서 같은 화면이 열립니다. 사용 환경에 맞는 방법 하나만 고르면 됩니다.

Installing NextSIM gives you the simulation engine and the browser tool (the NextSIM page, with its Run and Edit modes) together. There are four ways to install; every one of them ends with the same screen in your browser, so pick one that fits your machine.

Windows 설치 파일Windows installer

NextSim-Setup-v1.2.exe Windows 10/11 64비트 · Edge 또는 ChromeWindows 10/11 64-bit · Edge or Chrome

  1. 릴리스 페이지에서 NextSim-Setup-v1.2.exe를 내려받습니다.
  2. 설치 파일을 실행하고 안내에 따라 설치합니다. Python과 시뮬레이터가 모두 들어 있으므로 따로 설치할 것이 없습니다.
  3. 시작 메뉴나 바탕 화면의 NextSim을 실행합니다. 검은 콘솔 창이 열리고 몇 초 뒤 NextSim 창(브라우저)이 뜹니다.
  4. 첫 시뮬레이션으로 넘어갑니다.
  1. Download NextSim-Setup-v1.2.exe from the releases page.
  2. Run it and follow the installer. Python and the simulator are bundled, so there is nothing else to install.
  3. Launch NextSim from the Start menu or the desktop. A black console window opens, and a few seconds later the NextSim window (your browser) appears.
  4. Continue with your first simulation.
콘솔 창이 곧 서버입니다. 이 창을 닫으면 NextSim이 종료됩니다. 서버는 이 PC 안에서만 접속할 수 있고(http://127.0.0.1:8000/, 이 포트가 사용 중이면 다음 빈 포트), 실제 주소는 콘솔 창 상단에 표시됩니다.
The console window is the server. Closing it quits NextSim. The server only accepts connections from this PC (http://127.0.0.1:8000/, or the next free port), and the address it settled on is printed at the top of the console.
"Windows의 PC 보호" 창이 뜨면 추가 정보 → 실행을 누르세요. 서명되지 않은 설치 파일을 실행할 때 Windows SmartScreen이 표시하는 경고입니다.
If "Windows protected your PC" appears, choose More info → Run anyway. It is SmartScreen's warning for an unsigned installer.

Docker Desktop 만 있으면 컴파일러 없이 저장소에서 바로 실행할 수 있습니다. 처음 실행할 때는 엔진을 컨테이너 안에서 빌드하므로 몇 분 걸립니다.

With Docker Desktop you can start straight from the repository without a local compiler. The first start builds the engine inside the container, so it takes a few minutes.

데이터는 호스트의 ./workspace/에 저장됩니다 (SimulationInput/, SimulationOutput/). 컨테이너를 처음 실행할 때 예제 네트워크가 이 폴더에 복사됩니다. 다른 위치를 쓰려면 NEXTSIM_WORKSPACE=~/nextsim-data docker compose up처럼 지정합니다.

Linux · WSL 배포판Linux · WSL package

nextsim-linux-x64-v1.2.zip Linux x86-64 또는 Windows + WSL2 · Python 3.9+Linux x86-64 or Windows + WSL2 · Python 3.9+

미리 빌드된 실행 파일과 예제 네트워크를 묶은 ZIP 파일입니다. 실행 파일이 완전히 정적으로 링크되어 있어 리눅스 배포판의 종류나 버전에 관계없이 동작하며, git·cmake·컴파일러·Docker가 필요 없습니다.

A ZIP of prebuilt binaries and example networks. The binaries are fully statically linked, so any Linux distribution works, and you need no git, cmake, compiler, or Docker.

  1. 릴리스 페이지에서 nextsim-linux-x64-v1.2.zip을 내려받아 압축을 풉니다. WSL을 사용한다면 Windows 폴더 (/mnt/c/...)보다 WSL 홈(~/) 안에 압축을 푸는 것이 몇 배 빠릅니다.
  2. Python이 없다면 설치합니다 (Ubuntu/WSL: sudo apt install python3 python3-venv).
  3. 실행 권한을 부여하고 시작 스크립트를 실행합니다. 처음 실행할 때는 Flask를 내려받느라 1~2분 걸리고, 그다음부터는 바로 시작됩니다. 브라우저는 자동으로 열립니다.
  1. Download nextsim-linux-x64-v1.2.zip from the releases page and unpack it. On WSL, unpacking inside your WSL home (~/) is several times faster than under a Windows folder (/mnt/c/...).
  2. Install Python if you don't have it (Ubuntu/WSL: sudo apt install python3 python3-venv).
  3. Mark the scripts executable and run the start script. The first run spends a minute or two fetching Flask; after that it starts immediately. Your browser opens on its own.
cd nextsim-linux-x64-v1.2
chmod +x start_web.sh scripts/*.sh Captain/build/bin/*
./start_web.sh

Windows에서는 start_web.bat을 더블클릭하면 WSL 안에서 start_web.sh가 실행됩니다. WSL이 없다면 PowerShell(관리자)에서 wsl --install을 실행한 뒤 재부팅하고, Ubuntu를 한 번 열어 초기 설정을 마친 다음 다시 실행하세요. 서버를 종료하려면 터미널에서 Ctrl+C를 누릅니다.

On Windows, double-click start_web.bat to run start_web.sh inside WSL. Without WSL, run wsl --install in an administrator PowerShell, reboot, open Ubuntu once to finish its setup, then try again. Stop the server with Ctrl+C in the terminal.

엔진 빌드Building the engine

저장소를 받고 서브모듈까지 가져온 뒤 프리셋으로 빌드합니다.

Clone the repository with its submodules, then build with the preset.

# 1. 소스 받기 (서브모듈 포함)
git clone --recursive https://github.com/AIxMobility/NextSim.git
cd NextSim

# 이미 --recursive 없이 받아 뒀다면
git submodule update --init --recursive

# 2. 빌드 (저장소 루트에서)
cmake --preset release --fresh -S Captain
cmake --build build/captain/release -j
# 1. Get the source, submodules included
git clone --recursive https://github.com/AIxMobility/NextSim.git
cd NextSim

# If you already cloned without --recursive
git submodule update --init --recursive

# 2. Build, from the repository root
cmake --preset release --fresh -S Captain
cmake --build build/captain/release -j

결과 바이너리는 build/captain/release/bin/에 생성됩니다. 웹 서버가 기본으로 찾는 위치가 바로 여기이므로, 이 경로로 빌드하면 별도 설정 없이 Run 모드의 실행 버튼(Run Selected Network)이 동작합니다.

The binaries land in build/captain/release/bin/. That is exactly where the web server looks by default, so building this way makes the run button in Run mode (Run Selected Network) work with no further configuration.

프리셋은 debug, release, relwithdebinfo 세 가지입니다. 특정 바이너리만 필요하면 타깃을 지정하세요:

Three presets exist: debug, release, and relwithdebinfo. To build just one binary, name the target:

cmake --build build/captain/release --target UnitTestsSimulation -j
README의 빌드 방법은 최신 내용이 아닙니다. cd Captain && cmake . && make는 소스 트리 안에 빌드 산출물을 만들고(Captain/bin/), 웹 서버는 그 경로를 확인하지 않습니다. 위의 프리셋 방식을 사용하세요.
The README's build recipe is out of date. cd Captain && cmake . && make builds in-source into Captain/bin/, which the web server never reads. Use the preset workflow above.
서브모듈 주의. NextSim_io는 .gitmodules에 main으로 적혀 있지만 실제로 고정된 커밋은 publictransit 브랜치에 있습니다. 따라서 git submodule update --remote는 쓰지 마세요. 이 명령은 잘못된 브랜치를 가져옵니다. --init --recursive로 고정된 커밋을 그대로 받으면 됩니다.
A submodule caveat. .gitmodules lists main for NextSim_io, but the pinned commit lives on publictransit. Avoid git submodule update --remote, which would fetch the wrong branch — use --init --recursive to take the pinned commits as they are.

웹 서버 실행Running the web server

cd NextSim
./start_visualizer.sh

Flask가 없으면 스크립트가 설치하고, 포트가 사용 중이면 비어 있는 포트를 찾아 서버를 실행합니다. python3 web_server.py로 직접 실행할 수도 있습니다.

The script installs Flask if it is missing and, if the port is busy, scans upward for a free one. You can also run python3 web_server.py directly.

웹 UI는 엔진을 빌드하지 않습니다. Run 모드의 실행 버튼은 이미 빌드된 바이너리를 사용할 뿐이며, 바이너리가 없으면 그 사실을 알리고 멈춥니다. 소스를 고쳤다면 직접 다시 빌드하세요. 또는 NEXTSIM_WEB_BUILD=1로 자동 빌드를 켜도 됩니다.
The web UI does not build the engine. The run button in Run mode uses the binaries that are already there and stops with a message if one is missing. Rebuild yourself after changing the source — or set NEXTSIM_WEB_BUILD=1 to have it build first.

  1. NextSIM을 엽니다. 홈 화면의 NextSIM 카드를 누르거나 http://localhost:8000/nextsim/로 접속하면 Run 모드로 열립니다. 상단바의 네트워크 버튼(폴더 아이콘, 처음에는 Select network)을 눌러 예제 네트워크 test를 선택합니다. 지도에 도로망이 그려집니다.
  2. Simulation 패널에서 Target scenario를 고르고 Run Selected Network를 누릅니다. 경로 생성부터 결과 적재까지 자동으로 진행되며, 작은 예제이므로 몇 초 안에 끝납니다.
  3. Space로 재생하고, 슬라이더로 원하는 시각으로 이동해 봅니다.
  4. 실제 도시 규모의 시뮬레이션을 보고 싶다면 bucheon을 실행해 보세요. 시나리오에 따라 수 분에서 수십 분이 걸립니다.

  2. In the Simulation panel choose a Target scenario and press Run Selected Network. Route generation through result loading runs on its own; this small example finishes in seconds.
  3. Press Space to play and scrub with the slider.
  4. For a city-scale run, try bucheon — minutes to tens of minutes depending on the scenario.
실행이 끝나면 이전 결과는 새 결과로 바뀝니다. SimulationOutput/에는 마지막 결과 하나만 남습니다(실행을 취소하거나 실행이 실패하면 이전 결과가 그대로 복원됩니다). 보관하고 싶은 결과는 실행 전에 다른 곳으로 복사해 두세요.
A finished run replaces the previous result. SimulationOutput/ keeps only the latest result (a cancelled or failed run puts the previous one back). Copy anything you want to keep somewhere else before running again.

설치 문제 해결Install troubleshooting

"Illegal instruction" 오류가 나거나 실행 파일이 바로 종료됩니다"Illegal instruction", or the engine dies immediately

CPU가 AVX2를 지원하지 않는 경우입니다. Linux에서는 grep -o 'avx2' /proc/cpuinfo | head -1 명령으로 확인할 수 있습니다. 소스에서 빌드한다면 이 플래그가 Captain/CMake/CompileOptions.cmake에 고정되어 있으므로 이 파일을 직접 수정해야 합니다.

Your CPU lacks AVX2; on Linux check with grep -o 'avx2' /proc/cpuinfo | head -1. For a source build the flag is hard-coded in Captain/CMake/CompileOptions.cmake, so you have to edit that file yourself.

Run이 "실행 파일이 없습니다" 오류로 실패합니다Run fails with "executable not found"

Windows: 설치 폴더의 engine\ 안에 exe 3개가 있는지, 백신이 격리하지 않았는지 확인하세요. ZIP: Captain/build/bin/에 실행 파일 3개가 있고 실행 권한이 있는지 확인하세요. 소스 빌드: 웹 UI는 엔진을 빌드하지 않습니다. 빌드 결과가 build/captain/release/bin/에 있는지 확인하고, 다른 곳에 빌드했다면 NEXTSIM_BIN_DIR로 그 위치를 지정하세요.

Windows: check that the three exe files are in the install folder's engine\ and that antivirus has not quarantined them. ZIP: check that the three binaries are in Captain/build/bin/ and executable. Source build: the web UI does not build for you — check the output is in build/captain/release/bin/, or point NEXTSIM_BIN_DIR at where you built.

Permission denied (ZIP)Permission denied (ZIP)

chmod +x start_web.sh scripts/*.sh Captain/build/bin/*

python3: command not found 또는 가상환경을 만들 수 없습니다python3: command not found, or no virtual environment

sudo apt update && sudo apt install python3 python3-venv

Flask가 이미 설치된 Python을 사용하려면 NEXTSIM_PYTHON=/path/to/python ./start_web.sh처럼 실행합니다.

To use a Python that already has Flask: NEXTSIM_PYTHON=/path/to/python ./start_web.sh.

WSL에서 localhost로 접속되지 않습니다localhost doesn't work on WSL

시작 스크립트가 실행될 때 이 문제를 감지하고 WSL 포워딩 설정을 자동으로 고치려고 시도합니다. 그래도 접속되지 않으면 터미널에 표시된 http://<IP>:8000/ 주소로 접속하거나, Windows에서 wsl --shutdown을 실행한 뒤 다시 시작하세요.

The start script detects this and tries to repair WSL's forwarding configuration. If it persists, use the http://<IP>:8000/ address printed in the terminal, or run wsl --shutdown from Windows and start again.

WSL에서 너무 느립니다It is very slow on WSL

NextSIM 폴더가 /mnt/c/... 아래에 있으면 파일 I/O가 매우 느립니다. ~/ 아래로 옮기세요.

File I/O under /mnt/c/... is very slow. Move the NextSIM folder under ~/.

포트 8000이 이미 사용 중입니다Port 8000 is already in use

기본 설정에서는 서버가 빈 포트를 자동으로 찾아 실행되고, 실제 주소는 시작 로그에 표시됩니다. 포트를 직접 정하려면 WEB_PORT=8100 ./start_web.sh처럼 실행합니다.

By default it scans for a free port and prints the address it settled on. To choose one yourself: WEB_PORT=8100 ./start_web.sh.

경고 때문에 빌드가 멈춥니다 (소스 빌드)A warning stops the build (source build)

-Werror가 기본으로 켜져 있어 경고도 오류로 처리됩니다. 컴파일러 버전이 달라서 새 경고가 발생한다면 CMake 옵션 CUBBYFLOW_WARNINGS_AS_ERRORS=OFF로 이 설정을 끌 수 있습니다.

Warnings are errors by default. If a different compiler version raises new ones, turn it off with the CMake option CUBBYFLOW_WARNINGS_AS_ERRORS=OFF.

NextSim_io를 찾을 수 없다는 오류가 나옵니다 (소스 빌드)It can't find NextSim_io (source build)

서브모듈을 받지 않은 상태입니다. git submodule update --init --recursive를 실행하세요. --remote는 쓰지 마세요. 이 옵션을 쓰면 고정된 커밋이 아니라 다른 브랜치를 가져옵니다.

The submodules are not checked out. Run git submodule update --init --recursive. Do not add --remote; it would fetch a different branch instead of the pinned commit.

차량이 나타나지 않거나 결과가 사라지는 등 시뮬레이션 자체의 문제는 개요의 문제 해결을 참고하세요.

For problems with the simulation itself — no vehicles, a vanished result — see troubleshooting in the overview.
