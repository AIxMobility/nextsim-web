네 가지 흔한 작업을 짧은 스크립트로 따라 합니다. 스크립트는 저장소의 NextCI/examples/tutorials/ 에 있고, 각자 서버를 띄웠다가 끝나면 끕니다. 예제 네트워크 bucheon 의 시나리오 0 에서 돌렸으며, 출력은 그때의 예시입니다. 시뮬레이션에 무작위성이 있어 실행할 때마다 값이 조금씩 다릅니다.

Four common jobs, each as a short script. The scripts live in NextCI/examples/tutorials/ in the repository; each starts its own server and stops it at the end. They were run on scenario 0 of the example network bucheon, and the outputs shown are from those runs. The simulation is stochastic, so values differ a little from run to run.

Before you start: finish the three setup steps in NextCI getting started, and make sure SimulationInput/config.txt says network=bucheon (network folder SimulationInput/networks/bucheon/).

1. 붐비는 도로의 상태를 1 분마다 기록하기Log the busiest roads every minute

5 분 동안 차량이 채워진 뒤 가장 붐비는 링크 세 개를 골라, 시나리오가 끝날 때까지 1 분마다 차량 수와 평균 속도를 CSV 에 씁니다.

After five minutes of fill-up, pick the three busiest links and write their vehicle count and mean speed to a CSV every minute until the scenario ends.

launch_and_connectsim_stepget_link_id_listget_link_vehicle_countget_link_mean_speed_mpsget_sim_time_millisis_finished
NextCI/examples/tutorials/t1_log_links.py
"""Tutorial 1: log the state of the busiest links to a CSV file every minute."""
import csv

from nextci import NextCIClient, NextCIStatusError


def busiest_links(client, n):
    """The n links with the most vehicles right now."""
    counts = {}
    for link in client.get_link_id_list():
        try:
            counts[link] = client.get_link_vehicle_count(link)
        except NextCIStatusError:        # intersection-internal links cannot be queried one by one
            pass
    return sorted(counts, key=counts.get, reverse=True)[:n]


with NextCIClient().launch_and_connect() as client, open("links.csv", "w", newline="") as f:
    client.sim_step(3000)                # the first 5 min fill the network
    links = busiest_links(client, 3)

    out = csv.writer(f)
    out.writerow(["time_s", "link_id", "vehicles", "mean_speed_mps"])
    while not client.is_finished():
        client.sim_step(600)             # 60 s
        t = client.get_sim_time_millis() / 1000
        for link in links:
            out.writerow([t, link,
                          client.get_link_vehicle_count(link),
                          round(client.get_link_mean_speed_mps(link), 2)])

살펴볼 점What to notice

  • get_link_id_list() 에는 교차로 내부 링크도 들어 있어, 개별 조회를 try 로 감싸고 NextCIStatusError 를 건너뜁니다.get_link_id_list() includes intersection-internal links, so per-link queries sit in a try that skips NextCIStatusError.
  • sim_step(600) 은 60 s 입니다. 1 사이클이 0.1 s 이기 때문입니다.sim_step(600) is 60 s, because one cycle is 0.1 s.
  • is_finished() 가 True 가 되면 반복이 끝납니다. 10 분 시나리오라 5 분 워밍업 뒤 다섯 번 기록합니다.The loop ends when is_finished() turns True; with a 10-minute scenario that is five records after the 5-minute warm-up.

2. 검지기로 교통량 · 점유율 · 통행시간 재기Measure flow, occupancy, and travel time with detectors

한 링크에 세 종류의 검지기를 붙입니다. 차로마다 E1 으로 교통량을, 한 차로에 E2 로 점유율을, 링크 전체에 E3 로 통행시간을 1 분 단위로 잽니다.

Put all three detector types on one link: E1 per lane for flow, E2 over one lane for occupancy, and E3 around the link for travel time, per minute.

add_detector_e1add_detector_e2add_detector_e3sim_stepflush_recordingsget_detector_flowget_detector_occupancyget_detector_mean_travel_timeget_link_lengthget_link_lane_count
NextCI/examples/tutorials/t2_detectors.py
"""Tutorial 2: measure flow, occupancy, and travel time with E1, E2, and E3 detectors."""
from nextci import NextCIClient

LINK = 20001453                          # 3 lanes, 243.9 m in the example network bucheon

with NextCIClient().launch_and_connect() as client:
    length = client.get_link_length(LINK)
    lanes = client.get_link_lane_count(LINK)

    # E1 at the middle of every lane, E2 over lane 1, E3 around the whole link
    for lane in range(lanes):
        client.add_detector_e1(detector_id=f"e1_{lane}", link_id=LINK,
                               lane_index=lane, pos=length / 2, freq=60.0)
    client.add_detector_e2(detector_id="e2_lane1", link_id=LINK, lane_index=1,
                           pos=10.0, end_pos=length - 10.0, freq=60.0)
    client.add_detector_e3(
        detector_id="e3_link",
        entries=",".join(f"{LINK}:{lane}:5.0" for lane in range(lanes)),
        exits=",".join(f"{LINK}:{lane}:{length - 5:.1f}" for lane in range(lanes)),
        freq=60.0,
    )

    client.sim_step(3000)                # 5 min warm-up
    print("time_s  flow_veh_h lane0/1/2   occupancy_%  travel_time_s")
    for _ in range(5):
        client.sim_step(600)             # 60 s = the detectors' aggregation interval
        client.flush_recordings()        # interval values update after a flush
        flows = [client.get_detector_flow(f"e1_{lane}") for lane in range(lanes)]
        print(f"{client.get_sim_time_millis() / 1000:6.0f}  {flows!s:22}  "
              f"{client.get_detector_occupancy('e2_lane1'):10.1f}  "
              f"{client.get_detector_mean_travel_time('e3_link'):12.1f}")

살펴볼 점What to notice

  • 검지기의 freq=60.0 과 스텝 간격 60 s 를 맞추면, 매 반복마다 새 구간 하나가 끝납니다.With the detectors' freq=60.0 matching the 60 s step, each loop closes exactly one interval.
  • 구간 값은 flush_recordings() 뒤에 갱신됩니다. 빠뜨리면 이전 구간 값이나 No detector interval record yet 오류를 받습니다.Interval values update after flush_recordings(); without it you get the previous interval or No detector interval record yet.
  • 점유율은 E2 에서만, 통행시간은 E3 에서만 채워집니다. E1 에 get_detector_occupancy() 를 부르면 0 이 나옵니다.Occupancy is filled only by E2 and travel time only by E3; get_detector_occupancy() on an E1 returns 0.
  • 교통량 300 veh/h 는 60 s 동안 5 대가 지나갔다는 뜻입니다.A flow of 300 veh/h means 5 vehicles passed in 60 s.

3. 같은 시점에서 여러 번 이어 돌려 보기Run the same moment several times

5 분 시점을 체크포인트로 저장하고, 거기서 2 분씩 다섯 번 이어 돌려 결과가 얼마나 흔들리는지 봅니다. 정책을 비교하기 전에 우연에 의한 차이가 어느 정도인지 아는 데 씁니다.

Save the 5-minute mark as a checkpoint and run two minutes from it five times, to see how much the result wobbles — useful for knowing how large chance differences are before comparing policies.

save_checkpointrestore_checkpointget_vehicle_countsim_step
NextCI/examples/tutorials/t3_replications.py
"""Tutorial 3: run the same two minutes several times from one checkpoint."""
import statistics

from nextci import NextCIClient

with NextCIClient().launch_and_connect() as client:
    client.sim_step(3000)                # at the 5-minute mark
    client.save_checkpoint("t300")       # keep the state in server memory
    start = client.get_vehicle_count()
    print("vehicles at the checkpoint:", start)

    counts = []
    for run in range(5):
        client.restore_checkpoint("t300")
        assert client.get_vehicle_count() == start   # the moment of restore matches the save
        client.sim_step(1200)            # two more minutes from there
        counts.append(client.get_vehicle_count())
        print(f"run {run}: vehicles after 2 min = {counts[-1]}")

    print(f"mean {statistics.mean(counts):.1f}, min {min(counts)}, max {max(counts)}")

살펴볼 점What to notice

  • 복원한 순간의 차량 수는 늘 저장 시점과 같습니다. 스크립트의 assert 가 이를 확인합니다.The vehicle count at the moment of restore always matches the save; the script's assert checks it.
  • 그 뒤의 결과가 조금씩 다른 것은 체크포인트가 난수 상태를 저장하지 않기 때문입니다. 차이의 크기는 네트워크와 시점에 따라 다릅니다.The runs differ afterwards because checkpoints do not save random-number state. How much depends on the network and the moment.
  • 서버를 새로 띄워도 출발점부터 조금 달라집니다. 이 문서를 만들며 같은 코드를 돌렸을 때 체크포인트 시점의 차량 수가 976 · 978 · 996 대였습니다.A fresh server also starts from slightly different traffic: running the same code while writing this page gave 976, 978, and 996 vehicles at the checkpoint.

4. 관심 구간만 micro 로, 나머지는 meso 로Micro for the study area, meso for the rest

가장 붐비는 링크 다섯 개만 micro 로 남기고 나머지 325 개를 meso 로 바꿔, 같은 시점에서 1 분을 돌렸을 때의 계산 시간과 차량 수를 전부 micro 인 경우와 비교합니다. NextSIM 의 하이브리드 방식을 코드로 확인하는 예제입니다.

Keep only the five busiest links micro, switch the other 325 to meso, and from the same moment compare one minute of computation time and vehicle count against all-micro — the hybrid idea of NextSIM, in code.

save_checkpointrestore_checkpointget_meso_link_id_listset_link_modeget_meso_lane_countget_meso_section_countget_meso_cell_vehicle_countget_vehicle_count
NextCI/examples/tutorials/t4_hybrid.py
"""Tutorial 4: keep the study area micro, switch the rest to meso, and compare."""
import time

from nextci import NextCIClient, NextCIStatusError


def busiest_links(client, n):
    counts = {}
    for link in client.get_link_id_list():
        try:
            counts[link] = client.get_link_vehicle_count(link)
        except NextCIStatusError:
            pass
    return sorted(counts, key=counts.get, reverse=True)[:n]


def total_vehicles(client, meso_links):
    """Vehicles on micro lanes plus vehicles inside meso cells."""
    n = client.get_vehicle_count()                   # counts micro lanes only
    for link in meso_links:
        for lane in range(client.get_meso_lane_count(link)):
            for cell in range(client.get_meso_section_count(link)):
                n += client.get_meso_cell_vehicle_count(link, lane, cell)
    return n


with NextCIClient().launch_and_connect() as client:
    client.sim_step(3000)
    client.save_checkpoint("t300")
    study = set(busiest_links(client, 5))            # the study area: the 5 busiest links

    # A. one minute with every link micro
    t0 = time.perf_counter()
    client.sim_step(600)
    print(f"all micro : {time.perf_counter() - t0:.2f} s wall, vehicles {client.get_vehicle_count()}")

    # B. from the same moment, everything outside the study area meso
    client.restore_checkpoint("t300")
    meso = [link for link in client.get_meso_link_id_list() if link not in study]
    for link in meso:
        client.set_link_mode(link, "meso")
    t0 = time.perf_counter()
    client.sim_step(600)
    print(f"hybrid    : {time.perf_counter() - t0:.2f} s wall, vehicles {total_vehicles(client, meso)}"
          f"  ({len(meso)} links meso, {len(study)} micro)")
    print("micro only:", client.get_vehicle_count())

살펴볼 점What to notice

  • meso 로 바꾼 링크의 차량은 사라지지 않고 셀로 옮겨집니다. 다만 get_vehicle_count() 는 micro 차로 위만 세므로, 전체는 total_vehicles() 처럼 셀을 더해야 합니다 (위 출력의 132 와 968).Vehicles on links switched to meso are not lost; they move into cells. get_vehicle_count() counts micro lanes only, so the total needs the cells added, as total_vehicles() does (132 versus 968 above).
  • 계산 시간은 이 컴퓨터에서 0.79 s → 0.31 s 로 줄었습니다. 컴퓨터와 네트워크에 따라 다릅니다.Computation time dropped from 0.79 s to 0.31 s on this machine; it depends on the machine and the network.
  • 차량 수가 1077 과 968 로 다른 것은 두 모형의 거동이 다르기 때문입니다. 정밀도와 계산 비용 사이의 선택이 바로 이것입니다.The vehicle counts differ (1077 and 968) because the two models behave differently — exactly the trade-off between detail and cost.
  • 링크 325 개를 바꾸는 데 약 2 s 가 걸렸습니다. set_link_mode() 가 호출마다 엔진의 연결 정보를 다시 계산하기 때문입니다.Switching 325 links took about 2 s, because each set_link_mode() call recomputes the engine's connection info.
